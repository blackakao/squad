# 소환 Entity 관리

Entity는 `data/entities/<entityId>.json`에 개체별로 저장한다. 스킬에는 Entity 정의를 복제하지 않고 `entityId`, 소환 수 `count`, 유지시간 `duration`, 동시 유지 수 `limit`를 저장한다.

## 스킬 편집 안에서 관리

1. 액션 종류를 **개체 소환**으로 설정한다.
2. Entity 선택 상자 위에서 이름·역할·태그를 검색한다. 선택하면 이름, 역할/AI, 아이콘, 설명, 능력치와 태그가 읽기 전용으로 표시된다.
3. **새 Entity**로 편집 창을 연다. ID는 소문자 영문·숫자·밑줄·하이픈으로 지정하거나 비워 자동 생성한다. 기존 ID는 수정할 수 없다.
4. **수정 → 기존 Entity 수정**은 같은 Entity를 참조하는 모든 스킬에 반영한다. 화면에 사용 스킬 수를 표시하며, **새 Entity로 저장**을 선택하면 독립된 정의를 만들고 현재 액션만 연결한다.
5. **복사**는 `_copy`, `_copy_2` 등의 새 ID로 즉시 생성하고 현재 액션에 연결한다. 복사본을 수정해도 원본은 변하지 않는다.
6. **사용 중인 Skill** 목록에서 다른 스킬로 이동할 수 있다. 현재 미저장 편집을 버리는지 확인한다.
7. **삭제**는 서버에 저장된 사용처를 검사한다. 참조가 남아 있으면 개수와 스킬 목록을 표시하고 삭제하지 않는다. 사용하지 않는 Entity를 삭제하면 현재 폼의 미저장 연결도 해제한다.

Entity 저장은 즉시 DB에 반영된다. Entity 생성/복사 후 **스킬 저장**을 눌러 연결 변경을 저장해야 한다. 스킬 편집을 취소해도 이미 저장한 Entity는 남으며 다시 선택할 수 있다.

## 능력치와 AI

역할은 근접·원거리·치유·방어·특수 분류이며, 실제 행동은 AI(근접/원거리/치유/설치형)가 결정한다. HP·MP·ST·공격력·마력·방어력·저항력·이동속도·공격 간격·시전시간·사거리를 독립적으로 설정한다. 아이콘은 `assets/...` 경로 또는 이미지 URL을 입력한다.

공격속도 값은 기존 엔진과 같은 **공격 간격(초)**이다. 작을수록 빠르다. 시전시간 0은 즉시시전이다. 설치형은 이동속도를 설정해도 자발적으로 이동하지 않는다. 치유 AI는 다친 아군에게 접근하여 회복한다. 일반 충돌로 설치형이 밀릴 수 있으며 지형 방벽 기능은 없다.

## 저장 전 전투 미리보기

Entity 편집에서 **미리보기**를 누르면 미저장 값으로 독립 캔버스에서 실행한다. 이동·공격·치유·투사체·시전은 실제 전투 함수를 사용한다. 공격 사거리 원, 아이콘/개체 크기, 누적 피해/치유, 남은 시전시간을 표시한다. 설치형은 사거리 안에 훈련 대상을 배치한다.

스탯을 바꾼 뒤 미리보기를 다시 누르면 새 값으로 시작한다. 원활한 관찰을 위해 훈련 대상 HP와 소환수 자원을 보충한다. 자원 지속력/전투 결과 밸런스 검증용은 아니다. 실제 편성·진행 중인 전투·기록·Entity 파일은 변경하지 않는다. 닫기/중지로 루프를 종료한다.

## API

| 메서드 | 경로 | 기능 |
| --- | --- | --- |
| GET | `/api/entities/` | 전체 Entity 배열 |
| GET | `/api/entities/<id>` 또는 `<id>.json` | 단일 Entity |
| POST | `/api/entities/` | 생성, 빈 ID 자동 생성, 기존 ID 충돌은 409 |
| PUT | `/api/entities/<id>` | 기존 정의 수정, ID 변경 불가 |
| DELETE | `/api/entities/<id>` | 삭제, 사용 중이면 409 |
| GET | `/api/entities/<id>/usages` | 참조 스킬의 ID/이름 배열 |

생성/수정 본문은 `entityId`, `name`, `description`, `icon`, `role`, `ai`, `tags`, `stats` 객체를 사용한다. `stats`에는 위의 11개 능력치가 필요하다. 설명·아이콘·태그는 생략 가능하며 AI 생략 시 역할에 따라 기본값을 정한다.

서버는 Entity 삭제와 스킬 저장을 동일 잠금 안에서 검증한다. 삭제 검사 직후 다른 요청이 참조를 추가하는 경합에서도 끊어진 참조를 만들지 않는다. 잘못된 ID, 경로 이동, 음수/무한대 등 유효하지 않은 능력치를 거부한다. 파일은 임시 파일 작성 후 교체한다.

전투 시작 시 Entity DB를 복사해 해당 전투의 정의로 사용한다. 공유 Entity 수정은 다음 전투에 반영되며 진행 중인 전투의 소환 능력치는 바뀌지 않는다.

## 기존 데이터 이전과 실행

기존 액션에 포함된 `summon` 정의는 처음 API를 읽을 때 Entity 파일로 자동 이전한다. 이름과 수치를 보존하며 반복 실행해도 중복 생성하지 않는다. Entity 파일을 먼저 저장하고 스킬 참조를 바꾼다. 기존 예제 3개는 이전 완료 상태다.

서버 코드가 추가되었으므로 실행 중인 구버전 `python server.py`는 재시작해야 한다. 브라우저도 새로고침한다.

검증: `node --test tests/skill-engine.test.cjs`, `python -B -m unittest discover -s tests -p test_entities.py`. 기존 전투 동작, 전투 시작 시 정의 복사, CRUD·복사 독립성·참조 삭제 제한·동시 요청·마이그레이션을 확인한다.
