# 전투 기록의 소유자 기여도

2026-10-13 완료. 새 일반 전투 기록과 headless 결과는 `contributionVersion: 1`을 저장한다. 기본 멤버는 편성 캐릭터/몬스터이며 영구·임시 소환수는 독립 멤버가 아니다.

## 집계 기준

- `js/battle-events.js`가 전투 전체 기여도를 누적한다. 최근 1,000건인 화면 이벤트 이력과 독립적이므로 긴 전투와 임시 소환수 제거 후에도 성과가 남는다.
- 실제 `owner`/`summoner`와 전투별 `ownerEventId`로 연결한다. 이름·저장 캐릭터 인덱스로 추측하지 않아 같은 이름, 양 진영의 동일 캐릭터 인덱스도 분리된다.
- 피해는 `hit`의 실제 HP+BP 피해, 치유는 `heal`의 HP 회복이다. 과잉 치유·HP 자원 drain은 기존 엔진 분류를 따른다.
- 적 편성 멤버 처치, HP 외 자원 회복, 스킬별 피해·치유와 시전 완료 횟수도 직접/소환수/총합으로 나눈다. 소환수 처치는 기존 시뮬레이터대로 캐릭터 처치 수에 넣지 않는다.
- 소유자의 받은 피해·사망·생존시간·잔여 자원에는 소환수 값을 더하지 않는다.
- 새 일반 기록의 전투시간은 `combatEventTick / 60`이다. 빨리 보기·배속에서도 진행한 전투시간으로 총 피해/시간과 총 치유/시간을 계산한다. 벽시계나 반올림한 DPS를 더하지 않는다. 전투 규칙·틱 진행 방식은 바꾸지 않는다.

## 저장과 표시

멤버에 `eventId`, `damageDealt`, `healingDone`, `kills`, `dps`, `hps`, `contribution`이 추가된다. `contribution`은 `direct`, `summon`, `total`, `groups`로 구성한다. 그룹은 소유자 내부의 `entityId + summonType` 기준이며 템플릿 이름, 서로 다른 객체 수 `count`, 기여도와 DPS/HPS를 저장한다. 같은 영구 객체의 재활성화는 개수를 늘리지 않는다. 런타임 객체 참조는 저장하지 않는다.

이름의 ▶ 버튼으로 총 기여·직접·소환수와 `노포 ×12 (임시)` 같은 묶음을 펼친다. 상세 이벤트의 source/target과 소환수 이름·소유자 ID는 그대로다. 선택 체크박스와 삭제 동작도 유지한다.

기존 기록은 멤버 ID·소유 관계가 없고 이벤트도 일부만 남을 수 있어 이름으로 재구성하지 않는다. **이전 기록 · 소유자별 기여도 정보 없음** 안내와 기존 값을 보존한다. 과거 소환수 행도 추측해서 삭제하지 않으며 새 전투부터 적용된다.

## 시뮬레이터

`characters`의 총 피해/치유/DPS/HPS/처치와 행동량은 동일한 공통 집계를 사용한다. `contribution`에서 직접·소환수·그룹별 상세를 조회한다. `summonTotals`는 이미 캐릭터 총합에 포함된 진단용 부분합이다. 팀/조합 합계에는 **characters만 한 번** 더한다. 분석 summary에는 직접/소환 피해·치유 합계, Markdown 보고서에는 분리된 피해와 전체 관측시간 기준 DPS를 제공한다. 이전 실행 결과는 재계산하거나 덮어쓰지 않는다.

## 검증

- Node 스킬·headless 165개: 반복 소환 12회, 동일 이름/ID 소유자, 영구 사망·재활성화, 치유/MP/처치, 1,000건 초과 이벤트, 초기화, 3대3 자동 소환 전투, 팀 중복 합산 방지, 재현성 포함.
- 격리 API + Chrome 기록 테스트: 직접 10 + 임시 84 + 영구 11 = 피해 105, 10초 DPS 10.5, 치유 20/HPS 2, 다른 소유자 피해 13 분리. 저장·새로고침·펼치기·원본 이벤트·3대3 목록 확인 및 1440px 화면 검수.
- Chrome gameLoop와 headless의 1대1/2대2/3대3 전투: 모든 이벤트와 총 피해/치유 비교 통과. 사용자 데이터는 복사본에서만 검증했다.
