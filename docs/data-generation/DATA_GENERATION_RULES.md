# 게임 데이터 생성 규칙

사용자 요청 → 실제 저장 구조·기존 예시·소비 코드 조사 → 필수 필드·제약 확인 → 생성 → 실제 저장소 등록 → 중복·참조·로드·장착 검증 → 결과 기록 순서로 진행합니다. 기존 콘텐츠는 삭제하거나 덮어쓰지 않습니다.

## 공통 원칙

- 실제 스키마·ID·카테고리·슬롯·능력치·효과·참조 방식만 사용합니다. 필요한 기능이 없으면 보고하고 시스템을 임의 확장하지 않습니다.
- 이름은 특징을 나타내며 단순 일련번호만 붙이지 않습니다. ID·이름 충돌을 확인합니다.
- 이번 아이템은 완성된 고정형입니다. 레벨·성장곡선·강화·등급·진화·랜덤 옵션·세트·드롭·경제 시스템을 추가하지 않습니다.
- 카테고리별 기준 성능을 100으로 보고 전체 가치를 대략 80~120 범위로 설계합니다. 모든 능력치를 80~120으로 설정한다는 의미가 아닙니다.
- 주 능력치를 줄인 만큼 소수의 작은 보조 능력치를 배분합니다. 단순 상위호환과 동일 조합 반복을 최소화합니다.
- 공식이 없는 능력치 가치 환산식을 게임 규칙으로 만들지 않습니다. 80~120은 초기 설계 목표이며 실전 성능 보장이나 검증된 종합 점수가 아닙니다.
- 생성 기준은 이 문서, 게임 목표 밸런스는 별도 `BALANCE_TARGETS.md`의 책임입니다. 전투 측정과 목표 변경은 이번 데이터 생성 작업 범위에 포함하지 않습니다.
- 검증은 격리한 데이터와 실제 서버·브라우저로 실행합니다. 테스트로 원본 캐릭터·스킬·장비 조합을 바꾸지 않습니다.

## 2026-10-10 배치 기준

[카테고리](../../data/categories.json)의 14개 행(무기 10, 방어구 4)이 대상입니다. 장신구·특수장비는 슬롯이며 독립 카테고리 행이 없습니다. 방어구는 카테고리당 상의 5개·하의 5개로 배분합니다. 슬롯을 새 카테고리로 만들지 않습니다.

[아이템](../../data/items.json)은 능력치를 최상위 필드에 저장합니다. 별도 stats, level, icon 필드를 추가하지 않습니다. 11개 능력치는 [ui.js](../../js/ui.js)의 ABILITY_ROWS를 따릅니다. 치명타는 아이템 능력치가 아니므로 사용하지 않습니다.

캐릭터 9명의 조사 시점 저장값은 HP 2,000~4,500, MP 100~200, ST 100~150, 공격 10~221, 마력 10~560, 이동속도 1~2.2, 방어 0~25, 저항 0~20입니다. 저장값에 장비·스탯이 포함될 수 있어 순수 기본 능력치로 단정하지 않습니다.

주 능력치 배율은 1.00/1.15/0.95/0.94/0.90/0.88/0.90/0.90/0.84/0.82입니다. 무기 정수 반올림 후 약 80~120%이며 방어구는 HP 정수, 방어·저항 소수 1자리입니다. 주 능력치 강화형은 보조가 없고 표준형은 ST 5입니다. 나머지는 HP 30~50, MP·ST 5~15, 이동속도 0.06~0.08, 저항 1 등 1~2개를 배분합니다. 방패 공격형은 공격 4, 방어구 공격형은 공격 3 또는 마력 4입니다. 방어구 주 능력치 묶음에 HP·저항 보조가 더해진 경우 목록에는 합산한 최종값을 표시합니다.

일부 능력치 우월 관계는 남습니다(정수 반올림, 단일 보조 방향). 특히 방어구는 상·하의 슬롯이 달라 단순 교체 비교 대상이 다릅니다. 모든 옵션이 높은 조합이나 완전 무작위 수치는 사용하지 않습니다. 기존 카테고리 사이의 큰 편차(지팡이 500 등)는 보존하며 카테고리 간 등가 성능을 주장하지 않습니다.

무기의 handType·attackType·attackRange·attackSpeed·castSpeed는 카테고리와 일치시킵니다. 로드 시 실제 정규화가 이 값들을 재적용하므로 개별 속도 특화는 speed(이동속도)로 표현합니다. 방패는 subWeapon, 나머지 무기는 mainWeapon에 등록합니다. both 무기는 실제 장착 시 양쪽을 허용하고 twoHand 무기는 기본 규칙에서 두 슬롯을 차지합니다.

아이콘은 기존 카테고리 매핑을 자동 사용하며 매핑이 없으면 기존 텍스트 fallback을 사용합니다. 개별 가상 경로를 만들지 않습니다. 기존 권투장비와 치유서의 공유 이미지 매핑은 보존합니다.

## 재현·검증

- [생성 도구](../../tools/generate_sample_items_20261010.py)는 날짜가 고정된 단일 배치입니다. 기본 dry-run, `--write`는 기존 배열 뒤에만 추가합니다. 이미 등록한 배치는 ID 충돌로 재실행을 거부하며 보고서도 덮어쓰지 않습니다.
- 이후 데이터 생성은 당시의 실제 예시·스키마를 다시 조사합니다. 이번 기준을 모든 미래 데이터에 무조건 적용하지 않습니다.
- [브라우저 검증](../../tests/test_generated_items.py)은 현재 배치의 ID·필드·수치·참조·카테고리·슬롯, 실제 정규화·장착·합산, API 저장·로드, 목록·선택·장착 유지 등을 검사합니다.
- 실제 이름·ID·최종 수치와 검증 결과는 [생성 기록](DATA_GENERATION_LOG.md)에 남깁니다.
