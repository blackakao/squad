## 작업 중 주의사항

- **문서 충돌:** TODO의 과거 일괄 읽기·갱신 규칙보다 최신 AGENTS를 우선한다. 과거 JS/GLB 혼용·머리만 팔레트 지원·다른 성별 수동 선택 허용은 현재 메인 화면 규칙이 아니다. 다른 문서는 이번에 정리하지 않았다.
- **GLB/Legacy:** 메인은 외부 GLB 전용, 절차형 JS는 [Legacy](../character-viewer-legacy.html)에 보존한다. GLB 후보/fallback에 JS를 섞지 않는다. 현재 머리·눈·의류·발·머리장비 팔레트 지원. `남성_`/`여성_` 및 과거 `male_`/`female_` 성별을 목록·무작위에 적용하고 무접두사는 공용이다. 레지스트리·폴더가 단일 원본이며 `randomAllowNone`·이전 비동기 응답 폐기 규칙을 유지한다([규격](CHARACTER_PARTS_GLB.md)).
- **조합 저장:** `sdCharacterAssembler.v1`은 게임 JSON과 별도인 개발용 로컬 프리셋이다. 과거 assetId 별칭을 유지하며 사라진 ID는 해당 카테고리만 해제한다([저장 구조](data_structure.md)). 외부 머리는 폴더 추가 후 목록 새로고침으로 장착한다.
- **미해결 자산:** 구형 `female_underwear_preview.glb`·`male_underwear_preview.glb`의 `Invalid typed array length: 20` 메모를 보존한다. 여성 오류는 이력에도 있으나 남성 개별 오류의 별도 보존은 확인하지 못했다. 새 `*_skinned_new.glb`의 재바인딩·초상화는 확인된 상태다. 구형 재-export/개발 목록 분리는 후속 범위이며 임의 삭제하지 않는다. 긴 머리·어깨 극단 자세 clipping도 미검수다.
- **Legacy 헤어:** `CrownHair`/`FrontHair`/`SideHair`/`BackHair`·Hair Anchor와 20종 독립 profile 유지. 공통 둥근 HairCap·Hairline 타원체·외부 실루엣용 InternalScalpCover를 재도입하지 않는다. 완료 판정은 실제 6방향 렌더 기준([뷰어](CHARACTER_VIEWER.md)).
- **클래스·쿨다운:** 캐릭터 이름이 클래스 키이므로 변경 시 스킬 `className`도 확인한다. 쿨다운 부여는 `skillCooldowns`·`skillCooldownTotals`를 함께 기록한다.
- **저장 계약:** 캐릭터 원본 배열 인덱스는 팀·전투 참조([캐릭터](CHARACTER_UI.md)). 아이템 원본 액션/자원 행 변경 시 보조 대상을 재선택한다. 선택 필드 `statModifiers`/`skillModifiers`는 원본 스탯·스킬을 바꾸지 않으며 단위·지속시간 0 의미는 원래 항목을 따른다. 참조 해제→아이템 삭제는 비원자적 저장([아이템](ITEM_MANAGEMENT.md)). 인벤토리는 수량 차감 없는 전체 카탈로그, 권투장비의 치유서와 동일 아이콘은 사용자 교체 대상([장비 UI](EQUIPMENT_UI.md)).
- **시너지·CP:** 공용 시너지는 기존 팀 `synergyRules` 배율과 다르다. 기본 빈 정의에서 실제 수치는 사용자 결정이며 현재 값은 데이터로 확인한다. 진영 이름 변경 시 조건 재선택, 공격/시전속도 시간 단위 유지([시너지](synergy/SYNERGY_SYSTEM.md)). CP는 저장하지 않고 `runtimeSynergyModifiers` 제외 빌드로 계산한다. 팀 CP를 개인 합으로 대체하거나 CP에 맞춰 사용자 수치를 바꾸지 않는다([CP](balance/COMBAT_POWER.md)).
- **기록·소환:** 과거 소유자 ID 없는 기록을 이름으로 역추정하지 않는다. `summonTotals`는 이미 포함된 부분합, 새 기록 시간은 틱/60([기여도](BATTLE_CONTRIBUTIONS.md)). `summonType` 생략은 임시, 영구도 종료 시 런타임 제거, 소환수만 생존해도 전투 유지. 야수 부활 확장 지점은 기존 영구 객체·명시적 HP만 받으며 대상·비용·자원·수명은 별도 설계([Entity](ENTITIES.md)).
- **재개 조건:** 시뮬레이터는 Node 22.8 이상. 이미지/Job API 변경 반영은 기존 서버 재시작 필요. 웹 Job은 서버 소유이며 새로고침은 안전하지만 서버 종료 시 현재 전투 후 중단한다. 결과 없는 활성 기록은 재시작 시 FAILED/journal로 보존하고 자동 재실행하지 않는다([안내](balance/SIMULATION_GUIDE.md)).
- **과거 측정:** V1 9명·V1.1 38명은 입력/엔진이 다르며 10,000회 119분은 과거 추정이다. 현재 engineHash와 달라질 수 있으므로 당시 inputSnapshot·원본 결과로 해석한다([성능](balance/PERFORMANCE.md), [보고서](balance/BALANCE_REPORT.md)). 2026-10-10 아이템 배치는 재등록하지 않는다. 80~120은 초기 목표이며 실측이 아니다. 광전사 테스트용 한손검 공격 30 등 이후 편집값을 생성 스냅샷으로 덮어쓰지 않는다([생성 기록](data-generation/DATA_GENERATION_LOG.md)).
- **환경:** 병렬 정적 요청의 간헐적 거부는 미해결 기록이며 대기열 64는 테스트 서버에만 적용됐다. 저장 검증은 격리/복사 데이터에서 수행한다. debug JSON·임시 영상·`.tmp_*`를 결과물에 포함하지 않는다. 다른 작업의 미커밋 변경·삭제 상태를 복원하거나 덮어쓰지 않는다.
