- 실제 시너지 수치는 시너지 관리에서 사용자가 결정합니다. 기본 데이터는 빈 배열입니다. %·AND/OR·적군/소환 전용 효과·시너지별 분석 통계는 후속 범위를 정한 뒤 진행합니다.

- 아이템 스킬 보조 대상인 원본 액션/자원 행을 수정하면 해당 아이템 편집에서 대상을 다시 선택합니다. 내장 자동 기본 공격 보조·곱셈 방식·임의 효과 내부 항목 확장은 별도 요청 시 범위를 정합니다.

- 야수 부활을 구현할 때 전용 대상 선택·비용·자원·수명 재설정 규칙을 먼저 정합니다. 현재 확장 함수는 기존 영구 객체와 명시적 HP만 받습니다. 전투 간 펫 소유 저장은 별도 설계입니다.

- 제품 서버에서 병렬 정적 파일 요청이 간헐적으로 거부되는 현상은 서버 작업 범위에서 별도로 검토합니다. 이번 UI 작업에서는 테스트 서버에만 대기열 64를 적용했습니다.

- 절차형 hair surface를 실제 제작 GLB 파츠로 교체할 경우 `CrownHair`/`FrontHair`/`SideHair`/`BackHair` 역할명과 Hair Anchor 규격을 유지합니다.
- 극단적인 애니메이션 자세에서 긴 머리와 어깨의 clipping을 별도 검수합니다.

## 작업 중 주의사항

- GLB 무작위 조합은 `server.py`의 카테고리 레지스트리와 폴더 목록이 단일 원본입니다. 새 카테고리는 레지스트리에 추가하고 `randomAllowNone` 정책을 명시합니다. 빠른 요청의 이전 load 결과를 상태에 되살리지 않으며, GLB 모드에 JS 파츠를 fallback으로 섞지 않습니다.
- GLB 성별 무작위 필터는 파일명의 시작 문자열 `male`/`female`을 사용합니다. 공용 파츠는 이 접두사를 붙이지 않습니다. 수동 선택은 의도적인 비교를 위해 다른 성별 파일도 계속 허용합니다.

- CP는 캐릭터에 저장하지 않으며 runtimeSynergyModifiers를 제거한 빌드의 공통 최종 능력치로 계산합니다. 과거 보고서의 승률을 현재 38명 CP의 승률처럼 해석하지 않습니다. Chrome 테스트는 복사 데이터에서만 저장합니다.

- 공용 시너지의 실제 정의와 계약은 `data/synergies.json`과 [SYNERGY_SYSTEM](synergy/SYNERGY_SYSTEM.md)을 먼저 확인합니다. 기존 팀 `synergyRules` 배율과 혼동하지 않습니다. 진영은 현재 문자열 키이므로 진영 이름을 바꾸면 관련 조건을 다시 선택해야 합니다. 공격속도·시전속도는 시간 단위입니다. 실행 중인 서버는 Job 스냅샷 변경을 적용하려면 재시작해야 합니다.

- 과거 전투 기록에는 멤버/소유자 ID가 없어 이름으로 역추정하지 않습니다. 기존 행/값을 보존하며 새 전투부터 소유자 합산을 적용합니다. `summonTotals`는 캐릭터 총합에 포함된 부분합이므로 팀 합계에 더하지 않습니다. 새 일반 기록의 시간은 전투 틱/60이고 피해 계산·AI·소환 생명주기는 그대로입니다.

- 아이템 `statModifiers`와 `skillModifiers`는 선택 필드입니다. 원본 캐릭터 배분 스탯/스킬은 수정하지 않고 장비 유효값을 계산합니다. 계수와 자원 비용 보정의 단위는 선택한 원래 항목과 같으며 지속시간 0의 무제한/비활성 의미도 기존 엔진을 따릅니다. 삭제는 참조 해제 후 아이템 저장 순서로, 두 저장은 원자적 트랜잭션이 아닙니다.

- 캐릭터 표 정렬은 화면용 목록에만 적용합니다. 원본 배열 인덱스는 팀·전투 참조에 사용하므로 재정렬하지 않습니다. 삭제 검증은 `tests/test_character_ui.py`의 격리 데이터에서 수행합니다.

- V1.1 실측은 38개 캐릭터 입력 스냅샷이며 과거 V1의 9개 캐릭터 결과와 다릅니다. 실행 도중 별도 소환수 생명주기 작업이 반영되어 현재 소스와 과거 결과의 engineHash가 다를 수 있습니다. 검증 결과는 `balance/jobs/`에 보존했고 게임 데이터 변경분은 되돌리지 않았습니다.
- 웹 작업은 서버 소유입니다. 브라우저 새로고침은 안전하지만 서버 종료 시 현재 전투 후 중단합니다. 재시작 시 결과 없는 활성 기록은 FAILED 및 journal로 보존하며 자동 재실행하지 않습니다.

- 기존 Entity는 `summonType` 생략 시 임시입니다. 영구 소환수도 전투 종료 시 런타임은 제거합니다. 소환수만 살아 있으면 계속 전투하는 기존 규칙은 유지합니다. 저장된 캐릭터/팀/Entity 사용자 데이터는 이번 변경에서 수정하지 않았습니다.

- 저장된 밸런스 보고서는 2026-10-10 22:12 KST 시작 시점의 캐릭터·장비·스킬 스냅샷을 사용합니다. 이후 아이템·진영·장비 설정 변경은 반영하지 않으며, 원본 JSON의 inputSnapshot으로 재현합니다. 이 작업에서 다른 작업의 데이터 변경을 되돌리지 않았습니다.

- 아이템 생성 도구의 2026-10-10 배치는 이미 등록됐습니다. 재등록하지 않으며 향후 생성은 당시 카테고리·기존 예시를 다시 조사합니다. 80~120은 초기 배분 목표로 실전 밸런스 측정값이 아닙니다.

- 인벤토리는 기존 전체 아이템 카탈로그이며, 장착해도 수량 감소나 목록 제거가 없습니다. 별도 아이템 관리 편집기·게임 계산식은 그대로 유지합니다.
