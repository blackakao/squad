# 종합전투력 V1 — Stat-based Combat Power

2026-10-14. 공식 버전은 stat-v1. 캐릭터의 전투 시작 전 빌드를 하나의 정수로 비교하는 초기 지표다. 승률·DPS 예측값이나 목표 밸런스가 아니며 캐릭터·아이템·스킬 수치를 자동 보정하지 않는다.

## 최종 능력치의 원본

실제 경로는 Character → applyCharacterStatAbilities → getCharacterCombatPower → calculateCombatPower다.

- [ui.js](../../js/ui.js)의 ROLE_STATS 계열 기본값, createCharacterAttributes 배분값, getStatAbilityBonus를 그대로 재사용한다. 개별 캐릭터 JSON에 저장된 hp/atk 등은 캐릭터 로딩 시 이 경로로 다시 계산된다.
- 기본 배분은 힘 str, 체력 vit, 민첩 agi, 집중 focus, 지능 int, 지혜 wis이다. DEX 필드는 없다. 10단위 투자, 항목별 50, 총 150 제한을 유지한다.
- 힘 → 공격력/방어, 체력 → HP/방어/저항, 민첩 → ST/이동/공격간격, 집중 → 공격력/기본 시전시간, 지능 → MP/마력/저항, 지혜 → MP/저항으로 변환된다.
- [equipment.js](../../js/equipment.js)의 아이템 직접 능력치와 statModifiers를 최종 계산에서 반영한다. 양손 무기 중복 제외, 추가 슬롯, 현재 선택된 세트의 equipment를 그대로 따른다. 원시 스탯을 CP에 다시 더하지 않는다.
- 기본 공격간격/시전시간은 무기 카테고리와 배분 보정에서 나온다. 아이템의 비무기 attackSpeed/castSpeed 직접 필드는 현행 최종 계산식에 합산되지 않는다. CP에서 엔진과 다르게 추가하지 않는다.
- runtimeSynergyModifiers는 파생·원시 스탯 모두 계산 전에 빈 객체로 대체한다. 전투 중 효과/현재 HP 대신 저장 빌드를 입력한다. 일시 버프, 패시브 발동, 변신, 부활 횟수, 팀 배율은 개인 CP에 포함하지 않는다.
- CP는 저장 필드가 아니다. 캐시도 없으며 렌더 때 현재 빌드로 다시 계산한다. 보고서에만 계산 스냅샷과 공식 버전·설정·입력 해시를 기록한다.

## 실제 엔진 조사

| 값 | 현재 엔진 의미 | V1 처리 |
| --- | --- | --- |
| HP | 체력 총량 | 피해 감소와 결합한 유효 HP |
| defense/resistance | rawDamage × (1 - clamp(value,0,100)/100) | 물리/마법 유입 50:50 가정 |
| atk/magic | 기본 물리/마법 피해, 회복, 스킬 계수의 입력 | 주력/보조 채널 잠재력 |
| attackSpeed | 초 단위 공격 간격, 최소 0.1; 60틱/초 | 작을수록 유리 |
| castSpeed | 기본 시전시간, 최소 0초 | 공격간격보다 긴 시전은 제한 요인 |
| speed | 매 전투 틱 이동량에 쓰는 값, 충돌·ST·AI 영향 존재 | 로그 환산, 작은 기여 |
| attackRange | 1단위=30px, 이동과 타겟 접근에 영향 | 로그 환산, 작은 기여 |
| MP/ST/BP/사용자 자원 | 비용·재생·탈진 등 행동 제약 | V1 직접 점수 제외 |

setCooldownAfterCast가 공격간격에서 시전시간을 빼므로 기본 주기는 대략 max(공격간격, 시전시간)이다. 하지만 독립 무기 공격은 getCharacterWeaponAttacks의 카테고리별 시간·사거리를 사용하고, 명시적 skill.castTime은 캐릭터 castSpeed를 대신한다. 따라서 아래 속도 환산은 빌드 잠재력 비교이며 개별 무기·스킬의 실제 처리량이 아니다. 무기 여러 개의 공격 횟수·집중 공격 페널티도 별도 평가하지 않는다.

## 분포와 기준점 선정

현재 38명의 최종 능력치를 먼저 계산했다. HP 2,000–4,990(중앙값 2,282), 공격력 10–221, 마력 10–560, 방어 0–40%, 저항 0–31.4%, 공격간격 0.5–2.5초, 시전시간 0–3초, 이동 1–2.3, 사거리 1–7이다. 미투자·무장비 캐릭터가 많아 전체 중앙값만 기준으로 삼으면 장비 빌드가 과장된다.

그에 따라 HP 3,000, 방어/저항 각각 15%, 공격 잠재력 100, 유효 주기 2초, 이동 1.5, 사거리 3을 고정 비교 기준으로 택했다. 이 가상 기준 빌드는 정확히 1,000 CP이다. 매번 현재 목록의 평균으로 재정규화하지 않으므로 캐릭터가 추가되어도 다른 빌드의 CP는 변하지 않는다. 무장비·미투자 빌드는 약 560, 현재 투자·장비 빌드는 대체로 800–1,700 범위다.

생존과 공격은 동등한 핵심 축으로 각각 45%, 이동·사거리는 AI와 전장 의존도가 높아 각각 5%로 둔다. 이는 분포와 단위를 검토한 **초기 설계 가중치**이며 실측 승률로 학습된 계수는 아니다.

## 중앙 공식과 설정

[combat-power.js](../../js/combat-power.js)의 COMBAT_POWER_CONFIG만 수정하면 모든 UI·진단 보고서에 적용된다. 공식·기준을 변경할 때 버전도 변경한다.

    D = clamp(defense, 0, 95) / 100
    R = clamp(resistance, 0, 95) / 100
    EHP = HP / (0.5 × (1-D) + 0.5 × (1-R))
    P = max(atk, magic) + 0.25 × min(atk, magic)
    T = max(0.1, attackSpeed, castSpeed)
    생존 = 450 × sqrt(EHP / (3000 / 0.85))
    공격 = 450 × sqrt((P / 100) × (2 / T))
    이동 = 50 × log(1 + speed) / log(1 + 1.5)
    사거리 = 50 × log(1 + attackRange) / log(1 + 3)
    CP = round(생존 + 공격 + 이동 + 사거리)

HP·방어 효과와 공격·속도 효과는 각 축에서 함께 평가하고 독립 점수로 중복 가산하지 않는다. 제곱근은 빠른 공격이나 큰 수치 하나의 지배력을 줄인다. 이동·사거리는 긴 사거리의 접근 우위가 선형으로 늘어난다고 가정하지 않고 로그로 완화한다.

공격과 마력을 동일하게 더하지 않는다. 스킬을 평가하지 않는 V1은 큰 채널 100%, 작은 채널 25%의 잠재력으로 본다. **마법을 쓰지 않는 빌드의 마력도 잠재력으로 점수가 붙는 한계가 있다.** 스킬 목록을 추측해 채널을 끄면 같은 스탯이 다른 CP가 되고 무기 교체 시 점수가 급락할 수 있어 V1은 능력치만으로 결정한다.

피해 감소 100%는 실제 엔진에서 해당 유형 면역이다. CP는 무한 EHP 방지를 위해 각 감소율을 95%에서 제한한다. 고정 피해·관통·상대 피해 유형 비중은 반영하지 않으며 95→100 상승을 구분하지 않는다. 낮은 기여 변화는 정수 반올림 때문에 표시 CP가 같을 수 있다.

잘못된 숫자/음수는 0으로 처리하고, 누락·비유한 공격간격은 기준 2초로 대체한다. 수치 상한 1e9와 주기 하한 0.1로 NaN/Infinity/오버플로를 방지한다. 모든 최종 점수는 유한한 비음수 정수다.

## 계산기 계약과 기여도

calculateCombatPower(finalStats)는 DOM·장비 저장소와 독립된 순수 함수이며 Node에서도 import할 수 있다. getCharacterCombatPower(character)는 게임의 공통 최종 계산기를 호출하는 빌드 어댑터다.

반환값: version, total, rawTotal, contributions(durability/offense/mobility/range), normalized, metrics(effectiveHp/power/interval). 어댑터는 finalStats도 반환한다. 기여도는 반올림 전 값으로 합하면 rawTotal과 같으며, 개별 표시값의 반올림 합은 total과 조금 다를 수 있다.

## 화면과 사용법

- 캐릭터 관리: 진영 다음 종합전투력 열, 숫자 양방향 정렬, 원본 배열 순서 보존.
- 스탯: 현재 저장된 빌드와 투자 초안의 예상 CP·증감 표시. +/−/초기화 시 즉시 갱신하며 **적용** 전에는 다른 화면의 저장된 빌드 CP는 변하지 않는다.
- 장비: 장비 세트 선택 아래에 기존 능력치 비교에 맞춰 **무장비 → 현재 장비**와 차이를 표시한다. 아이템 선택만으로 교체 예상 스탯을 보여주는 시스템은 없으므로 교체 전 미리보기는 추가하지 않았다. 장착/해제/세트 변경 저장 성공 후 즉시 다시 계산한다.
- 세 화면이 같은 빌드 어댑터를 사용한다. [combat-power-ui.js](../../js/combat-power-ui.js)는 숫자 포맷·툴팁·비교 마크업만 담당한다.
- 툴팁에는 최종 스탯 비교 지표와 스킬·소환·시너지·일시 효과 제외를 안내한다.

## 제외와 확장 경계

MP/ST는 행동에 중요하지만 사용 스킬·전투 길이·재생 없이 총량만 선형 평가하기 어렵다. BP/사용자 자원과 함께 직접 점수에서 제외한다. 지혜는 저항을 통해, 민첩은 이동·공격간격 등을 통해 평가된다.

스킬 계수·쿨타임·AoE·CC·치유·패시브·아이템 skillModifiers, 영구/임시 소환수의 기여도, AI, 팀 시너지는 제외한다. 스킬 미사용 마력, 캐릭터와 독립 무기의 서로 다른 시간/사거리, 추가 무기 수, 자원 부족은 실제 성능과 괴리를 만들 수 있다.

향후 Skill/Summon Contribution, 자원 지속력, 공격 유형별 사용률, 팀 시너지 적용 CP를 **별도 항목**으로 검토한다. 현재 개인 CP에 팀 시너지를 영구 합산하지 않는다.

## 실제 결과와 시뮬레이터 비교

[38명 CP·최종 스탯·기여도·과거 비교](COMBAT_POWER_RESULTS.md), [분석용 전체 JSON](COMBAT_POWER_RESULTS.json).

실데이터 최고는 승려 1,675, 흑마법사 1,560, 마법사 1,446이다. 승려는 공격 170/공격간격 0.5에서 공격 기여 1,182가 발생한다. 미투자·무장비 캐릭터(최저 561)와 약 3배 차이가 있지만 기본 HP 2,000/공격 10/마력 10과 비교한 차이다. 기사 1,181은 생존 기여 625로 탱커의 내구를 반영한다. 마법사 마력 560은 시전 2.5초로 완화되어 다른 장비 빌드의 3배로 튀지 않는다.

2026-10-10의 실제 1,000회 3v3 결과와 **그 보고서의 inputSnapshot을 V1으로 재계산한 CP**를 비교했다. 과거 승려는 CP 1,635인데 승률 29.88%/DPS 14.25, 마법사는 CP 1,405인데 승률 99.55%/DPS 206.49다. 이는 큰 순위 역전이다. V1의 단순 시간 잠재력은 실제 스킬/무기 경로·자원·타겟 접근을 반영하지 못한다. 현재 CP 공식을 승률 예측용으로 쓰기에는 부족하다. 스킬/AI 중 어떤 원인이 지배적인지는 통제 전투 없이 단정하지 않는다.

현재 38명 빌드와 과거 9명 빌드는 다르고 엔진도 이후 변경되었다. 과거 승률을 현재 CP 옆에 현재 성능처럼 붙이지 않는다. 새 대규모 전투는 실행하지 않았으며 기존 스냅샷을 재분석했다. 캐릭터 수치나 승률에 맞춰 가중치를 강제로 변경하지 않았다.

CP는 빌드 수치 평가, [시뮬레이터](SIMULATION_GUIDE.md)는 실제 엔진 반복 전투, [Balance Targets](BALANCE_TARGETS.md)는 사용자가 결정하는 목표다.
