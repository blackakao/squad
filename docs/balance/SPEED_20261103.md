# 2026-11-03 전투 테스트 속도 개선

## 조건과 변경

측정 PC: Intel Core i7-1065G7, 논리 CPU 8개, 메모리 약 7.74 GiB, Node v24.21.0. 게임 데이터는 수정하지 않고 [고정 입력](../../balance/benchmarks/20261103/input.json)을 사용했습니다. Seed 12345, 전장 400×300, 전투별 가상 시간 제한 600초입니다.

입력 SHA-256: `900728d3a4758566d0a17d78421ca545e6d6bef1b3a0bec1159d46bdb1da5d09`.

기존 1:1 100회 CPU profile의 가장 큰 비용은 `getSkillById`와 내부 배열 검색으로 약 4.70초였습니다. 3:3에서는 해당 조회가 약 5.20초였고 액션 정규화도 약 2.70초였습니다. 고정 스냅샷 전용 스킬 ID 인덱스를 사용해 반복 선형 검색을 없앴습니다. 첫 일치와 반환 객체의 동일성을 유지하며, 실제 게임에서 편집되는 스킬 목록은 변경하지 않았습니다. 상태 확인용 매 틱 유닛 배열 복사도 제거했습니다.

추가로 Worker마다 독립된 실제 전투 엔진을 만들고 반복 재사용합니다. 부모가 편성과 Seed를 순서대로 생성하므로 작업자 수나 완료 순서에 의해 전투가 바뀌지 않습니다. 최종 결과를 battleId 순으로 정렬한 뒤 기존 집계기를 호출합니다. 중단/실패 시 추가 배정은 멈추고 진행 중인 전투는 회수합니다. 전투 틱, AI, 스킬, 피해 계산, 가상 시간은 줄이지 않았습니다.

## 10,000회 목표

동일한 1:1 10,000회에서 Worker 4개는 **745.476초(12분 25초)**, Worker 8개는 **566.766초(9분 27초)**였습니다. **8개 설정으로 이 PC/스냅샷에서 10분 목표를 달성했습니다.** 3:3 10,000회는 측정하지 않았으며 모든 데이터/PC/부하 조건에서 10분을 보장하지 않습니다.

[실측 요약](../../balance/benchmarks/20261103/parallel4-10000-1v1.json), [전체 전투 원본](../../balance/benchmarks/20261103/parallel4-10000-1v1.result.json).

진행 실측: 1,000회 118.81초, 2,000회 203.46초, 5,000회 409.41초, 8,000회 609.99초, 10,000회 전투 종료 745.17초입니다. 표의 총 시간은 엔진 초기화·전투·집계까지이며 최종 파일 직렬화/쓰기 시간은 별도입니다. 측정 중 서버 테스트와 다른 개발 작업도 있었으므로 PC가 유휴 상태일 때의 보장 시간이 아닙니다. 전투 길이와 스킬 구성, CPU 부하에 따라 달라집니다.

전체 결과 SHA-256: `c6cd522c4b7f5f0e84e4426efb9318aca6009e5344e1aeab9244c62495268c8b`.

Worker 8개 별도 1,000회는 85.763초였습니다. 8개 10,000회는 1,000회 72.18초, 2,000회 119.25초, 5,000회 287.87초, 8,000회 440.34초, 10,000회 전투 종료 566.34초였습니다. 작업자 수뿐 아니라 서로 다른 시점의 PC 부하/JIT 차이도 포함됩니다.

[Worker 8개 실측 요약](../../balance/benchmarks/20261103/parallel8-10000-1v1.json), [10,000회 원본](../../balance/benchmarks/20261103/parallel8-10000-1v1.result.json). 두 10,000회 실행의 전체 전투 해시가 위 값으로 같으며 전투 결과가 동일합니다.

최종 요약 파일 저장 완료시각과 run.startedAt의 차이로 확인한 저장 포함 시간은 4개 746.318초, **8개 567.580초(약 9분 28초)**입니다. 위 wallSeconds에는 최종 파일 쓰기가 제외되어 있어 별도로 기록했습니다.

빠르게 실행하려면 **1 vs 1 → 상세 설정 → 동시 전투 계산 8개 → 10,000회**를 선택합니다. 자동 설정은 다른 작업의 CPU 여유를 위해 최대 4개를 유지합니다. 8개는 CPU 사용량이 높으며 더 적은 코어의 PC에서는 실제 가용 수로 제한됩니다.

## 검증

- 병렬 전투와 순차 전투의 Seed·순서·결과·집계 일치, 진행률, 중단 시 in-flight 회수, 작업자 초기화/소스 불일치 실패, 0회 중단·설정 검증: 신규 핵심 테스트 4개 통과.
- 실제 Node worker를 사용하는 서버 테스트 5개 통과. 단일 Job 제한·저장·이력/복구·중단·오류 경로 유지.
- 저장된 최적화 전후 1:1/3:3 각 100회의 전체 전투 JSON과 집계 JSON 완전 일치 확인.
- UI와 Seed 설명·설정 연결은 정적 검토. 브라우저 자동 테스트와 전체 엔진 회귀는 실행하지 않았습니다.

사용법: 전투 테스트 상세 설정에서 동시 계산 수를 선택합니다. 자동은 100회 미만 순차, 그 이상은 가용 논리 CPU 절반(최대 4개)입니다. 수동 1~8개도 가용 CPU·전투 수로 제한됩니다. CLI는 `--workers` 옵션을 사용합니다. Python 서버가 이미 실행 중이면 새 설정/API 반영을 위해 재시작해야 합니다.

재측정 도구: `node balance/simulator/benchmark.cjs <label> <count> <teamSize> <workers>`. 이 명령은 위 고정 입력을 재사용하며 게임 데이터를 저장하지 않습니다.
