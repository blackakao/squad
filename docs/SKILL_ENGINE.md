# 스킬 엔진 상세 규칙

구현 순서와 전체 완료 내역은 [스킬 엔진 업데이트 내역](SKILL_ENGINE_CHANGELOG.md)을 참고한다.

스킬 관리 → 추가/수정에서 설정한다. 기존 `/api/skills`로 저장되며 캐릭터에 장착하면 자동 전투에서 실행된다.

## 설명과 몬스터 스킬

스킬의 공통 `description` 필드는 수정 창의 설명란에서 입력한다. 목록의 설명 컬럼에는 최대 120자로 요약하고, 마우스를 올리면 전체 설명을 볼 수 있다. 설명이 비어 있는 기존 스킬은 액션 효과를 문장으로 자동 요약한다. 전체 원문은 저장·재로드 시 보존한다.

몬스터 추가/수정 창의 **사용 스킬**에서 여러 스킬을 선택할 수 있다. `skillIds` 배열로 저장하며 목록에도 표시한다. 전투에서는 캐릭터와 같은 자원·시전시간·쿨타임 규칙으로 사용한다. 장착 스킬을 사용할 수 없으면 기존 기본 공격/회복을 수행한다.

이동 액션이 포함된 스킬은 원거리에서 사용해도 투사체를 생성하지 않는다. 시전 완료 시 돌진·순간이동 또는 대상 강제 이동을 실행하고 이후 액션을 순서대로 실행한다.

## 시전시간

`castTime`은 초 단위다. 0이면 즉시시전, 양수이면 해당 시간 동안 시전하며 이동을 멈춘다. 빈칸/null/필드 누락은 기존 유닛 시전시간을 사용한다. 기본 공격/회복과 장비 연결 공격에도 적용된다. 명시한 값은 능력치와 합산하지 않는 최종 시간이다.

기존 직업 스킬에는 0.5초, 즉시시전 공격과 드렁큰 올리지에는 0초를 넣었다. 원거리 대상 중심 효과의 투사체 이동시간은 별도다. 시전과 소환 수명은 60틱/초로 계산하여 배속과 즉시 결과 계산에 반영한다. 채널링은 아래 설정으로 사용한다.

### 전투 계수

계산계수 필드에서 `actualDamageTotal`(시전자의 전투 누적 실제 HP+BP 피해, 과잉 피해 제외), `moveDistanceTotal`(자동 이동·돌진·순간이동·강제 이동의 실제 누적 거리 / 사거리 단위), `targetEffectStacks`(적용 대상의 모든 상태·버프 중첩 합계), `targetEffectIdStacks`(입력한 효과 ID와 일치하는 대상 효과의 중첩 합계), `ownedSummonCount`(살아 있는 자기 소환수 수)를 선택할 수 있다. 기존처럼 %는 기준값 × 입력값 / 100, 고정 계산은 기준값 + 입력값이다. 기본 계수 설정은 변경하지 않는다.

피해·회복 적용 시 계산하므로 투사체는 도착 시점, 광역은 각 대상의 적용 시점 값을 사용한다. 누적 피해에는 주기 피해도 포함하며 이번 타격은 계산 후 합산한다. 전체 중첩은 시전자·분류를 구분하지 않고 모두 합산한다. 특정 ID 중첩도 시전자와 상태·버프 종류를 구분하지 않고 정확히 같은 ID의 중첩을 합산하며, ID가 비어 있으면 저장을 막는다. 이동 거리는 충돌 보정·초기 배치를 제외한다. 전투 초기화 시 누적값을 0으로 돌린다.

`previousActualDamage`는 같은 스킬 실행에서 바로 앞 액션이 모든 대상에게 준 실제 HP+BP 피해 합계다. `executionActualDamage`는 현재 실행에서 앞선 피해 액션들이 준 실제 피해 누계다. 두 필드 모두 과잉 피해를 제외한다. 예를 들어 피해 액션 다음의 자신 회복 액션에 `previousActualDamage` 50%를 쓰면 실제 피해 절반을 회복한다.

`previousActualHealing`은 바로 앞 액션이 모든 대상에게 실제로 회복한 HP·MP·ST·BP 합계다. `executionActualHealing`은 현재 실행의 앞선 회복 액션들이 회복한 실제 수치 누계다. HP·MP·ST는 최대치를 넘은 양을 제외한다. 예를 들어 회복 액션 다음 적 피해 액션에 `previousActualHealing` 100%를 사용하면 실제 치유량만큼 피해를 주므로 치유→피해 전환을 구성할 수 있다. 피해→치유는 앞서 설명한 실제 피해 계수를 회복 액션에 사용한다.

실행 결과 계수가 있는 스킬은 액션 순서를 보장한다. 원거리 액션은 투사체가 적중한 뒤 다음 액션을 실행하고, 적중 전에 대상이 사라지면 해당 액션 결과를 0으로 두고 다음 액션을 계속한다. 광역·연쇄는 대상별 결과를 합산한다. 실행할 대상이 없는 액션도 직전 피해·치유 결과를 0으로 만든다. 채널링은 각 반복마다 새 실행 컨텍스트를 사용한다. 주기 효과가 나중에 발생시킨 피해·치유와 패시브로 별도 실행된 결과는 원래 실행 결과에 추가하지 않는다.

`resourceSpentTotal`은 이번 스킬 시전에 실제로 지불한 HP·MP·ST·BP의 합계다. `hpResourceSpent`, `mpResourceSpent`, `stResourceSpent`, `bpResourceSpent`는 자원별 실제 지불량이다. 고정값·최대치 비율·현재치 비율 비용을 차감한 전후 차이로 기록한다. 일반 시전과 투사체에 전달하며, 채널링은 최초 결제량을 매 반복에서 참조하되 다시 결제하지 않는다. 패시브는 해당 패시브가 지불한 비용을 자신의 실행 결과로 사용한다. 시전 중단 또는 사망으로 액션이 실행되지 않아도 이미 지불한 자원은 환불하지 않는다.

이 값은 시전자 자신의 스킬 비용만 나타낸다. 대상 자원 감소량은 아래의 별도 실행 결과 계수를 사용한다.

### 대상 자원 감소

`drain_resource` 액션은 `drainResource`로 HP·MP·ST·BP 중 하나를 선택하고, 일반 계수 합계만큼 대상 자원을 감소시킨다. 자원은 0 아래로 내려가지 않으며 요구량이 잔여량보다 크면 실제 잔여량만 성공한 것으로 계산한다. 자원이 이미 0인 대상은 선택·광역·연쇄 후보에서 제외한다. 액션별 사거리, 최소 거리, 저HP 조건, 대상별 쿨타임, 광역 반경·최대 대상 수, 연쇄 규칙과 투사체를 지원한다.

HP 자원 감소는 피해와 구분하며 방어력·저항력·BP·피해 무시를 우회한다. HP가 0이 되면 사망 판정은 수행하지만 일반 `hit`·`damaged` 이벤트와 피해 통계는 만들지 않는다. 모든 성공한 감소는 `resource_drain` 전투 이벤트에 실제 감소량과 자원 종류를 기록한다.

`previousResourceDrained`는 직전 자원 감소 액션이 모든 대상에게 성공한 감소량 합계이고 `executionResourceDrained`는 현재 스킬 실행의 누적 성공량이다. 원거리 액션은 투사체 적중 뒤 값을 확정하며 광역·연쇄는 대상별 실제 감소량을 합산한다. 이를 후속 ST 회복 등에 사용하면 적 MP 소진 성공량에 따른 자원 획득을 구성할 수 있다.

### 대상 HP 조건과 대상별 쿨타임

액션의 `targetHpBelow`는 대상의 현재 HP 비율 상한(%, 경계 포함)이다. 기본값 100은 제한 없음이다. `targetCooldown`은 동일 시전자의 같은 스킬·액션이 동일 대상에게 다시 적용되기까지의 초 단위 간격이며 기본값 0은 제한 없음이다. 다른 시전자·액션·대상은 독립적으로 계산한다.

대상 선택과 실제 적용 시 모두 검사하며, 광역·연쇄도 조건을 통과한 대상으로 최대 인원을 채운다. 소환은 시전자를 검사한다. 적용을 시도할 때 대상별 쿨타임을 시작하므로 면역으로 효과가 막히거나 실제 수치 변화가 없어도 간격을 소비한다. 투사체 발사 시 예약하지 않으며 도착 시 검사한다. 조건이 뒤늦게 불충족되어도 이미 지불한 시전 자원은 환불하지 않는다. 지속 효과를 부여한 뒤의 개별 주기 틱에는 이 조건을 재적용하지 않는다. 전투 초기화 시 대상별 쿨타임을 제거한다.

### 채널링

스킬 공통값 `channel`은 `{duration:0, interval:1, interruptOnDamage:true}`가 기본이다. 유지시간 0이면 기존 단발 실행이다. 양수이면 일반 시전 뒤 첫 간격부터 전체 액션을 반복하며, 종료 시점의 반복도 포함한다. 간격이 유지시간보다 길면 액션이 실행되지 않는다. 매번 액션별 대상을 다시 검증하고 대상이 없으면 해당 액션을 건너뛴다.

자원은 최초 시전 시 한 번 지불하고 쿨타임은 채널링 완료·중단 시 시작한다. 자동 이동과 다른 시전은 정지한다. 기절·사망은 항상 중단하고 침묵은 장착 스킬을 중단한다. 피해 중단 옵션은 HP 또는 BP의 실제 손실(주기 피해 포함)에 적용하며 초기 일반 시전에는 적용하지 않는다. 이미 발사한 투사체는 중단 후에도 도착한다. 패시브는 채널링 설정을 사용하지 않는다.

상태창에 남은 채널링 시간을 표시한다. 전투 이벤트는 `channel_start`, `channel_tick`, `channel_complete`, `channel_interrupt`를 기록하며 정상 종료 시에만 `cast_complete`가 한 번 발생한다. 초기화·전투 종료 시 예약된 반복을 제거한다.

### 횟수형 효과

상태·버프의 `effect.uses`에 1~100을 지정하면 `consumeOn` 조건이 발생할 때마다 남은 횟수를 1회 소모한다. 0은 횟수 제한 없음이다. 조건은 `hit`(자신이 실제 피해를 줌), `damaged`(자신이 실제 피해를 받음), `heal`(자신이 실제 회복을 실행), `cast_complete`(자신의 시전 완료) 중 하나다. 피해·회복은 실제 적용량이 0보다 커야 소모한다. `consumePeriodic`이 꺼져 있으면 주기 피해·회복 이벤트는 소모 조건에서 제외한다.

횟수형 능력치 버프는 해당 행동을 수행할 때까지 적용된 뒤 이벤트 처리 단계에서 소모된다. 남은 횟수가 0이 되면 즉시 제거하고 원래 능력치를 복구한다. 지속시간과 횟수를 함께 사용하면 먼저 끝나는 조건이 효과를 제거한다. 재적용은 지속시간과 사용 횟수를 초기값으로 갱신한다. 한 행동에 조건이 같은 횟수형 효과가 여러 개면 각각 1회씩 소모한다. 전투 상태 표시에는 남은 횟수가 함께 나타난다.

버프 계산 모드 `damage_immunity`는 다음 피해를 HP·BP 계산 전에 완전히 무시한다. 소모 조건은 항상 `damaged`로 정규화한다. 주기 피해는 `consumePeriodic`을 켠 경우에만 무시하고 횟수를 소모한다. `uses:0`이면 지속시간 또는 해제 전까지 모든 해당 피해를 무시한다. 피해 무시로 실제 피해가 0이면 일반 피격 패시브와 다른 횟수형 피격 효과는 발동·소모하지 않는다.

### 피해 대리 수신

버프 계산 모드 `damage_proxy`는 버프를 받은 대상의 피해 일부를 버프 시전자에게 전달한다. `proxyPercent`는 원래 피해에서 맡을 비율(1~100%), `proxyPriority`는 분배 순서(0~999, 낮을수록 먼저), `proxyScope`는 `all`·`basic`·`skill` 중 하나다. 기본 공격은 슬롯이 `basic`인 피해이며 주기 피해와 필드 피해를 포함한 나머지는 스킬 피해로 취급한다.

- 여러 보호자가 있으면 우선순위와 효과 적용 순서대로 원래 피해의 설정 비율을 맡는다. 앞선 보호자가 배정받은 뒤 남은 양보다 비율 몫이 크면 남은 양만 맡고, 최종 잔여분을 원래 대상이 받는다.
- 각 분배분은 받는 유닛 자신의 보호막·방어력·저항력·피해 무시를 따로 적용한다. 보호자가 사망했거나 적 진영으로 바뀌었거나 자기 자신이면 해당 효과를 건너뛴다.
- 대리 수신한 피해는 다시 다른 보호자에게 전달하지 않는다. 이 규칙으로 보호 고리와 무한 재귀를 차단한다. 상태이상은 이동하지 않는다.
- 공격자의 실제 피해와 같은 실행의 피해 결과에는 모든 수신자의 실제 HP·BP 감소 합계를 한 번만 더한다. 수신자별 받은 피해 기록은 각자에게 남긴다. 과잉 피해는 실제 피해에서 제외한다.
- 원래 공격은 `hit` 이벤트 한 번을 만들고 실제로 피해를 받은 유닛마다 `damaged` 이벤트를 만든다. 대리 수신에는 `damage_redirect` 이벤트를 추가한다.

## 액션별 대상 선정

각 액션은 자신의 `target`(적군/아군/자신), `rangeMode`, `rangeValue`로 대상을 독립적으로 찾는다. 적 피해와 아군 회복을 한 스킬에 넣어도 각각 해당 진영에 적용된다. 이동 액션도 편집기에서 사거리를 설정할 수 있다.

- 시전 시작은 실행할 대상이 있는 액션이 하나 이상이면 가능하다. 대상이 없는 액션만 생략하며 자원과 쿨타임은 스킬당 한 번 적용한다.
- 살아 있고 해당 액션 사거리 안에 있는 대상을 선택한다. 기존 시전 대상이 조건에 맞으면 유지하고, 아니면 가까운 대상을 찾는다. HP/MP/ST 회복은 해당 자원이 부족한 대상만 선택하며 대체 대상은 잔여 비율이 낮은 순, 거리 순이다. BP는 부족 조건 없이 부여한다.
- 자신 중심 광역은 반경 안의 유효 대상 유무로 시전을 결정한다. 자신 대상으로 지정한 광역 회복도 주변 아군을 회복할 수 있다.
- 시전 완료 시 대상과 사거리를 다시 검사한다. 기존 대상이 사망하거나 멀어지면 액션별로 새 대상을 찾는다. 한 액션의 실패가 다른 진영을 대상으로 하는 액션까지 취소하지 않는다.
- 원거리 피해/회복은 액션별 투사체를 보낸다. 발사 뒤에는 해당 대상을 추적하며, 사거리를 벗어나도 도달하면 적용한다. 대상이 죽으면 그 투사체만 소멸한다. 명중 시 다른 액션을 재실행하지 않는다.
- 이동 포함 스킬은 투사체 없이 액션 순서대로 실행하고, 이동 후의 위치에서 후속 액션 사거리를 검사한다. 원거리 투사체들의 실제 명중 순서는 이동거리에 따라 달라질 수 있다.
- 시전 중 범위 표시는 각 액션의 현재 후보 대상을 따라가고, 발사 후에는 해당 투사체의 대상 중심으로 표시한다.

## 이동과 충돌

이동 액션은 `Dash`, `Teleport`, `Knockback`, `Pull`, `Push`를 지원한다. 돌진과 순간이동은 시전자를 움직인다. 넉백과 밀치기는 대상을 시전자 반대 방향으로, 끌어오기는 시전자 방향으로 움직인다. 넉백과 밀치기는 현재 같은 물리 규칙을 사용하며 데이터에서 의도를 구분한다.

- 돌진은 대상까지 거리 중 `distance × 10%`만 이동한다. 경로에 다른 살아 있는 유닛이 있으면 충돌 거리 앞에서 멈춘다.
- 순간이동도 같은 거리 비율을 사용하고 경로 중간 유닛은 통과한다. 목적지가 다른 유닛에게 점유되어 있으면 이동하지 않는다.
- 강제 이동은 `distance`를 사거리 단위의 절대 거리로 사용한다. 다른 유닛 또는 전장 경계를 만나면 가능한 지점까지만 이동한다.
- 기절·이동 불가는 시전자 자신의 돌진과 순간이동을 막는다. 강제 이동을 받는 대상의 기절·이동 불가는 이동을 막지 않는다. 강제 이동만 있는 스킬은 이동 불가 상태의 시전자도 사용할 수 있다.
- 실제 이동한 거리만 이동 거리 누적 계수에 더한다. 일반 프레임 충돌 보정과 초기 배치는 누적하지 않는다. 강제 이동 성공 시 `forced_move` 이벤트에 실제 이동 거리와 방식을 기록한다.

## 최소 거리

피해·회복·이동 액션의 사거리 영역에서 `minRange`를 설정한다. 기본값과 기존 데이터의 누락값은 0(제한 없음)이며, 음수나 유효하지 않은 값도 0으로 정규화한다. 단위는 최대 사거리와 같다.

- 시전자가 지정 대상을 선택할 때 `최소 거리 ≤ 대상 거리 ≤ 최대 사거리`를 만족해야 한다. 시전 시작과 완료 때 모두 검사하며, 해당 액션에 유효 대상이 없으면 생략한다. 모든 액션에 대상이 없으면 자원을 소모하지 않고 시전을 시작하지 않는다.
- 최대 사거리는 액션의 특정값 또는 시전자의 주장비 사거리다. 최소 거리가 최대보다 크면 그 액션은 대상을 선택할 수 없다. 자동으로 최소 거리를 낮추거나 후퇴하지는 않는다.
- 자신 대상·소환·자신 중심 광역에는 최소 거리를 적용하지 않는다. 대상 중심 광역에서는 중심 대상 선정만 제한한다. 그 주변의 다른 타격 대상에는 최소 거리를 적용하지 않으므로 고리 모양 범위를 만드는 설정이 아니다.
- 발사된 투사체는 기존 규칙대로 대상을 추적한다. 발사 뒤 가까워져도 명중한다.

## 광역 범위

피해/회복 액션에 `area`(원형 반경), `areaCenter`(`target`/`self`), `maxTargets`를 지정한다. 반경은 기존 사거리와 같은 단위이며 내부적으로 `ATTACK_RANGE_UNIT`을 곱한다.

- 반경 0은 단일 대상, 최대 대상 수 0은 반경 안 전체다.
- 대상은 영향받을 진영, 중심은 원의 위치다. 적군 + 자신 중심은 주변 적 공격, 아군 + 자신 중심은 주변 아군 회복이다. 자신 대상으로 광역 설정 시 자신 진영에 적용된다.
- 살아 있는 해당 진영 개체를 중심에서 가까운 순으로 선택한다. 소환수도 포함한다. 피해/회복은 각 대상에게 독립 적용한다.
- 대상 중심은 투사체 명중 위치, 자신 중심은 시전 완료 시 시전자 위치를 사용한다. 자신 중심 효과는 투사체를 기다리지 않는다.
- 회복 자원을 BP/MP/ST로 바꾸면 광역 보호막/자원 회복이 된다.
- 지속 장판(`create_field`), 부채꼴, 직선은 별도 확장 대상이다. 연쇄는 아래의 별도 대상 선정 방식으로 지원한다.
- 시전 중 전장 바닥에 반투명 원과 점선 경계, 시전 진행 테두리를 표시한다. 아군 공격은 파랑, 아군 회복은 초록, 적군은 빨강이며 스킬명과 단계가 함께 표시된다. 대상 중심 원은 대상 이동을 따라가고 자신 중심 원은 시전자를 따라간다. 투사체 도달까지 범위를 유지하고 발동 위치에는 0.4초간 표시를 남긴다. 즉시시전도 발동 표시가 보이며 반경은 실제 효과 판정과 같다.

## 연쇄 대상

피해·회복 액션의 **추가 연쇄 횟수**(`chainCount`)는 기본 0(꺼짐), 최대 20이다. **연쇄 거리**(`chainRange`)는 기본 3이며 사거리와 같은 단위다. 추가 2회는 첫 대상 포함 최대 3명이다. `maxTargets`가 양수이면 첫 대상을 포함한 총 인원에도 이 제한을 적용한다.

첫 대상은 기존 최소·최대 사거리 규칙으로 선택한다. 첫 명중 순간 살아 있는 같은 대상 진영 중 직전 대상에서 연쇄 거리 이내인 가장 가까운 미방문 대상을 찾고 반복한다. 후속 대상에는 시전자와의 사거리 제한을 적용하지 않는다. 같은 개체는 한 번만 적용하며, 다음 대상이 없으면 중단한다. HP/MP/ST 회복은 해당 자원이 부족한 개체만 이어지고 BP는 제한 없이 부여한다. 피해와 회복량은 매 대상 동일하며 감쇠는 없다.

연쇄가 켜지면 원형 광역 대신 연쇄로 처리한다. 기존 광역 값은 보존하고 편집기에서 숨기며, 연쇄를 0으로 돌리면 다시 적용한다. 자신 대상 연쇄는 자신에서 시작해 같은 진영으로 이어진다. 이동·소환 액션에는 연쇄를 적용하지 않는다.

첫 대상까지는 기존 시전·투사체 규칙을 사용한다. 최초 명중 시 나머지 연쇄를 즉시 적용하고, 경로는 0.4초간 선으로 표시한다. 단계별 이동 투사체나 추가 시전·자원 비용·쿨타임은 없다. 첫 투사체의 대상이 죽으면 해당 액션은 취소된다.

## 소환

`summon_entity` 액션은 시전자 주변에 같은 진영의 개체를 생성한다. Entity 정의는 독립 DB에 저장하며 스킬 편집 화면 안에서 선택·생성·수정·복사·삭제한다. 자세한 API와 사용법은 [Entity 관리](ENTITIES.md)를 참고한다.

| 필드 | 의미 |
| --- | --- |
| entityId | Entity DB 참조 ID |
| summonCenter | `self`는 시전자 주변, `target`은 액션이 선택한 대상 주변 |
| inheritStats | HP·MP·ST·공격력·마력·방어력·저항력·이동속도별 소환자 계승 비율(0~1000%) |
| count, limit | 한 번에 1~10체, 같은 시전자·같은 스킬의 동시 유지 1~20체 |
| duration | 수명(초), 0이면 죽을 때까지 유지 |
| protectOwnerPercent | 소환자가 받을 원래 피해 중 소환수가 대신 받을 비율(0~100%) |
| protectOwnerScope | `all`·`basic`·`skill` 중 피해 대리 범위 |
| protectOwnerPriority | 여러 피해 대리 효과의 처리 순서(0~999, 낮을수록 먼저) |
| transferStateScope | `none`·`all`·`general`·`physical`·`magic` 중 해로운 상태이상 이전 범위 |
| transferStatePriority | 여러 소환수 중 상태이상을 받을 순서(0~999, 낮을수록 먼저) |

Entity의 `stats`에서 HP·MP·ST·공격력·마력·방어력·저항력·이동속도·공격 간격·시전시간·사거리를 편집한다. 소환수는 기존 이동·공격·치유·충돌·피격에 참여한다. 근접/원거리 AI는 물리 공격, 치유 AI는 마력 기반 회복을 한다. 설치형 AI는 자발적 이동을 하지 않는다. 별도 장착 스킬은 없다.

주인이 죽어도 수명까지 남으며 소환수만 남아도 전투가 계속된다. 사망/만료된 소환수도 기록에 별도 이름과 DPS를 남기며 주인 DPS에 중복 합산하지 않는다. 다음 전투 시작/초기화 시 이전 소환수를 제거한다.

한 진영의 살아 있는 소환수는 최대 40체다. 소환만 하는 스킬은 한도에 도달하면 자원을 쓰지 않고 다음 스킬/평타로 진행한다. 동일 스킬의 여러 소환 액션은 한도를 공유한다. 사망/만료 후 다시 소환할 수 있다.

소환수는 설정한 범위의 소환자 피해를 대신 받을 수 있다. 피해 대리는 원래 피해를 우선순위대로 나누며 소환자와 각 소환수의 보호막·방어력·면역을 따로 적용한다. 소환수가 사망하거나 만료되면 즉시 후보에서 빠진다. 해로운 상태이상 이전은 새로 부여되는 `add_state`에만 적용하며 설정한 효과 분류가 맞는 살아 있는 소환수 한 체에게 옮긴다. 이전된 상태가 소환수의 면역에 막혀도 소환자에게 되돌아오지 않는다.

일반 액션의 `target`에 `summon`을 지정하면 같은 진영 전체가 아니라 시전자가 직접 소유한 살아 있는 소환수만 선택한다. 피해·회복·자원 감소·강제 이동·상태·버프·해제와 지속 필드에 사용할 수 있으며 광역 반경과 최대 대상 수도 적용된다. 다른 아군이 소환한 개체와 일반 아군은 후보에서 제외한다. 이를 통해 소환수 강화, 회복, 자원 회수, HP 피해를 이용한 희생 효과를 기존 액션 조합으로 구성할 수 있다.

`summonCenter: target`은 액션의 `target`·최소 거리·최대 사거리로 살아 있는 중심 대상을 선택한다. `ally`는 시전자 자신을 제외한 아군을, `enemy`는 적군을 고른다. 소환수의 진영과 소유자는 중심 대상과 관계없이 항상 시전자 기준이다. 기존 데이터와 기본값은 `self`다.

`inheritStats`는 Entity의 기본 능력치에 소환 순간 시전자의 현재 전투 능력치 비율을 더한다. HP·MP·ST는 현재 잔량이 아닌 최대값을 사용한다. 생성된 소환수는 계산 결과를 독립적으로 보관하므로 이후 소환자의 능력치가 바뀌어도 다시 계산하지 않으며 Entity 원본 JSON도 변경하지 않는다. 설치형 AI의 이동속도는 계승 설정과 관계없이 0이다.

설치형도 일반 개체 충돌로 밀릴 수 있으며 방벽 지형은 아니다.

`command_summon` 액션은 시전자가 직접 소유한 살아 있는 소환수만 제어한다. `hold`는 이동·공격·시전·채널링을 멈추고, `release`는 Entity에서 소환될 때 저장한 AI와 이동속도로 복귀한다. `recall`은 소환수를 시전자 옆의 충돌 가능한 위치로 이동시키며, `dismiss`는 소환 해제로 사망 처리한다. 반경과 최대 대상 수를 설정하면 여러 소환수에게 같은 명령을 내릴 수 있다. 다른 시전자의 소환수에는 적용되지 않는다.

## 지속 지역 효과

`create_field` 액션은 대상 또는 시전자의 현재 위치를 복사해 고정 원형 필드를 만든다. 생성 뒤 대상이나 시전자가 이동하거나 시전자가 사망해도 위치와 남은 시간은 변하지 않는다. 전투 종료·중단·초기화 때 모든 필드를 제거한다. Entity 미리보기에서는 실제 전투 필드를 만들지 않는다.

| 필드 | 의미 |
| --- | --- |
| `fieldEffect` | `deal_damage`, `heal`, `drain_resource`, `move`, `add_buff`, `add_state` 중 반복할 효과 |
| `fieldEffectDuration` | 필드가 부여하는 상태·버프의 독립 지속시간 |
| `fieldCenter` | `target`은 선택 대상 위치, `self`는 시전자 위치 |
| `fieldRadius` | 원형 반경. 0보다 커야 한다 |
| `duration` | 유지시간(초). 0이면 전투가 끝날 때까지 유지 |
| `fieldInterval` | 적용 간격(초). 0보다 커야 한다 |
| `maxTargets` | 매 적용 시 선택할 최대 대상 수. 0이면 제한 없음 |
| `fieldMoveType` | 강제 이동 필드의 `Push`·`Knockback`·`Pull` |
| `fieldDistance` | 매 적용 시 이동시킬 거리. 1~10 |

`target`은 필드가 영향을 줄 진영을 결정하고 `fieldCenter`는 생성 위치만 결정한다. 매 간격마다 고정 위치 안의 살아 있는 대상을 다시 선택한다. 회복은 선택 자원이 부족한 대상부터, 자원 감소는 해당 자원이 남은 대상만 고른다. 강제 이동은 고정된 필드 중심을 기준으로 바깥쪽으로 밀치거나 중심으로 끌어당긴다. 속박을 무시하지만 유닛 충돌과 전장 경계에서 멈추며, 필드가 생성된 뒤 시전자가 이동하거나 사망해도 방향 기준은 바뀌지 않는다. 상태·버프 필드는 각 주기마다 기존 효과 부여 규칙을 실행하며 필드 수명과 부여 효과 수명을 독립적으로 설정한다. 면역·중첩·갱신·해제 규칙도 일반 효과와 같다. 대상별 쿨타임도 각 적용에 검사한다. 같은 위치의 여러 필드는 서로 합쳐지지 않고 독립적으로 실행한다.

첫 적용은 한 간격 뒤다. 지속시간과 적용 시점이 정확히 같으면 마지막 한 번을 적용하고 만료한다. 지속시간이 간격보다 짧으면 적용 없이 만료한다. 각 적용은 그 시점의 시전자·대상 능력치로 계수를 다시 계산하지만, 지연된 결과를 원래 스킬의 후속 액션 계수로 돌려주지는 않는다.

필드는 전투 화면에 반투명 원과 외곽선, 이름, 남은 시간으로 표시한다. 아군의 회복·버프 필드는 녹색, 강제 이동 필드는 청록색으로 구분한다. `field_create`, `field_tick`, `field_expire` 이벤트를 발행한다. 현재 필드 내부의 소환 실행은 지원하지 않는다.

## 변신

`transform` 액션은 시전자 자신에게 하나의 전투 형태를 적용한다. 형태 ID와 표시 이름, 지속시간, 계산 방식, 능력치 변경값을 편집한다. 지속시간 0은 사망·전투 종료·다른 변신 적용 전까지 유지한다.

- 변경 가능한 값은 공격력·마력·방어력·저항력·이동속도·사거리·공격 간격·기본 시전시간이다. `flat`은 고정값, `percent`는 효과 적용 전 기본 능력치에 대한 비율을 더한다.
- 한 유닛에는 변신 하나만 유지한다. 새 변신은 기존 변신을 먼저 제거해 원래 값을 복구한 다음 새 값을 적용한다. 같은 변신 재사용도 지속시간을 새로 시작한다.
- 일반 능력치 버프와 변신은 같은 기본 능력치에서 더한다. 예를 들어 기본 공격력 10, 고정 버프 +5, 변신 +100%면 최종 공격력은 25다. 복리 계산하지 않는다.
- 공격 간격은 최소 0.1초, 사거리는 최소 1, 나머지 능력치는 최소 0이다. 만료·교체·사망·전투 초기화 시 변신 수치만 제거하고 함께 적용된 일반 버프는 유지한다.
- 전장 효과 목록에 형태 이름과 남은 시간을 표시하고 `transform_start`, `transform_end` 이벤트를 발행한다. 현재 외형 이미지·역할·AI·장착 스킬·자원 종류는 바꾸지 않는다.

## 커스텀 자원

캐릭터와 몬스터는 편집 화면에서 기본 자원 외에 직업별 자원을 정의할 수 있다. 저장 형식은 `customResources` 배열이며 ID, 표시 이름, 전투 시작 초기값, 최대값을 가진다. ID는 영문 소문자·숫자·`_`·`-`만 사용하고 한 유닛 안에서 중복될 수 없다. 초기값은 0~최대값으로 보정한다.

스킬은 커스텀 자원을 `custom:<id>`로 참조한다. 스킬 비용의 고정값·최대값 비율·현재값 비율, 회복, 자원 감소, 주기 회복, 지속 지역 회복·감소에 사용할 수 있다. 대상에게 해당 자원 정의가 없으면 비용을 지불할 수 없고 회복·감소량은 0이다. 정의가 삭제되어도 기존 스킬의 참조 문자열은 보존되며 편집기에 `정의 없음`으로 표시한다.

```json
{
  "customResources": [
    { "id": "soul", "name": "영혼 포인트", "initial": 0, "max": 100 }
  ]
}
```

```json
{
  "resourceCosts": [
    { "resource": "custom:soul", "mode": "fixed", "value": 20 }
  ]
}
```

전투 유닛은 원본 정의와 분리된 현재값을 가지며 전투 초기화 때 초기값으로 돌아간다. 현재 전투 화면에 커스텀 자원 전용 막대는 표시하지 않으며, 장비에 의한 최대값 변경과 계수 필드별 커스텀 자원 선택은 후속 확장 대상이다.

## 캐릭터별 장비 규칙

캐릭터는 `equipmentRules`로 기본 장비 구조의 예외를 설정한다.

| 필드 | 의미 |
| --- | --- |
| `extraWeaponSlots` | 추가 무기 슬롯 수. 0~5 |
| `twoHandSingleSlot` | `true`면 양손 무기를 슬롯 하나에 착용 |

추가 무기 슬롯에는 한손 무기를 착용할 수 있다. `twoHandSingleSlot`이 활성화된 캐릭터는 양손 무기도 주무기·보조무기·추가 무기 슬롯에 각각 착용할 수 있다. 비활성 상태의 양손 무기는 기존처럼 주무기와 보조무기를 함께 점유한다. 추가 슬롯의 장비 능력치는 다른 슬롯과 동일하게 합산하지만 기본 공격의 공격 타입·공격 간격·장착 공격 스킬은 주무기, 그다음 보조무기만 사용한다.

```json
{
  "equipmentRules": {
    "extraWeaponSlots": 5,
    "twoHandSingleSlot": false
  }
}
```

추가 슬롯 수를 줄이면 범위를 벗어난 슬롯 참조는 다음 캐릭터 저장 시 제거된다. 같은 아이템 ID를 여러 슬롯에 넣어도 양손 무기의 능력치는 한 번만 합산한다. 장비 탈착 잠금, 무게와 무게 패널티는 아직 지원하지 않는다.

캐릭터의 `equipmentSets`에는 최대 3개의 장비 프리셋을 저장한다. `activeEquipmentSet`이 선택한 세트의 0부터 시작하는 순번이며, 선택된 세트의 장비를 기존 `equipment` 필드에도 복사해 능력치와 무기 공격 계산에 사용한다. 기존 단일 장비 데이터는 불러올 때 자동으로 `세트 1`이 된다. 장비 화면에서 현재 세트를 복제하거나 다른 세트로 전환하고 삭제할 수 있으며, 아이템 삭제 시 모든 프리셋에서 해당 참조를 함께 제거한다.

`swap_equipment_set` 액션은 자신 또는 아군의 장비를 `equipmentSetIndex`로 지정한 1~3번 세트로 교체한다. 대상에게 해당 순번의 세트가 없으면 유효 대상에서 제외되어 액션이 실패한다. 교체하면 최대 HP·MP·ST·BP, 공격·방어 능력치, 사거리, 공격 타입, 기본 공격 스킬과 독립 무기 구성이 새 세트를 따른다. 현재 HP·MP·ST·BP는 새 최대치를 넘을 때만 잘라내며 현재 효과, 변신, 스킬 쿨타임은 유지한다. 새 무기는 교체 직후 한 공격 주기 동안 대기하므로 세트 반복 교체로 즉시 공격할 수 없다.

## 전투 진입 대기와 부활

캐릭터의 `battleRules`에서 전투 진입 지연과 부활을 설정한다. 몬스터와 소환수에는 현재 편집 UI를 제공하지 않는다.

| 필드 | 의미 |
| --- | --- |
| `entryDelay` | 전투 시작 뒤 진입할 때까지의 초. 0이면 처음부터 전장에 배치 |
| `reviveCount` | 한 전투에서 가능한 부활 횟수. 0~10 |
| `reviveDelay` | 사망 후 다시 전장에 나타날 때까지의 초 |
| `reviveHpPercent` | 부활할 때 회복할 최대 HP 비율. 1~100 |
| `reviveMpPercent` | 부활할 때 회복할 최대 MP 비율. 0~100 |
| `reviveStPercent` | 부활할 때 회복할 최대 ST 비율. 0~100 |
| `reviveInvulnerable` | 부활 직후 모든 피해와 HP 자원 감소를 무시하는 시간(초). 0이면 없음 |
| `revivePosition` | `death`: 사망 위치, `start`: 전투 시작 때 배치된 진영 위치로 복귀 |

진입·부활 대기 중인 캐릭터는 살아 있는 유닛이 아니므로 이동, 충돌, 대상 선택, 광역 효과, 필드 효과에 참여하지 않는다. 상태창에는 대기 종류와 남은 시간을 표시한다. 진입할 때는 HP가 가득 찬 상태로, 부활할 때는 설정한 HP와 BP 0으로 같은 위치에 돌아온다. MP·ST·커스텀 자원의 현재값과 스킬 쿨타임은 부활 전 값을 유지한다. 사망할 때 상태·버프·변신·채널링은 정리된다.

```json
{
  "battleRules": {
    "entryDelay": 0,
    "reviveCount": 1,
    "reviveDelay": 3,
    "reviveHpPercent": 50,
    "reviveMpPercent": 100,
    "reviveStPercent": 100,
    "reviveInvulnerable": 1,
    "revivePosition": "start"
  }
}
```

팀에 살아 있는 유닛이 없어도 진입 또는 부활 대기자가 있으면 전투를 계속한다. 대기자까지 모두 소진된 진영만 패배하며 양쪽이 같은 틱에 전투 가능 인원을 모두 잃으면 무승부다. 소환수는 부활 횟수와 무관하며 기존 수명·사망 규칙을 따른다. 자동 부활과 스킬 부활은 시작·사망 위치 선택과 부활 직후 무적을 지원하며, 예비대는 자동 보충·영구 교대·시간제 교대·임시 증원을 지원한다.

## 팀 전투 규칙 덮어쓰기

팀 편성 화면에서 팀별 전투 계산 배율을 저장한다. 전투 시작 시 아군과 적군 규칙을 각각 복사하므로 전투 중 팀 데이터를 수정해도 진행 중인 전투에는 반영되지 않는다.

| 필드 | 기본값 | 적용 범위 |
| --- | --- | --- |
| `damagePercent` | 100 | 해당 진영이 주는 기본 공격·스킬·주기·필드 피해 |
| `healingPercent` | 100 | HP·MP·ST·BP·커스텀 자원 회복 |
| `resourceCostPercent` | 100 | 액티브·채널링·패시브 스킬의 실제 자원 비용 |
| `cooldownPercent` | 100 | 액티브·채널링·패시브 스킬 재사용 대기시간 |

```json
{
  "name": "팀1",
  "battleRules": {
    "damagePercent": 110,
    "healingPercent": 90,
    "resourceCostPercent": 120,
    "cooldownPercent": 80
  }
}
```

각 배율은 0 이상이며 서로 곱하지 않고 해당 계산 단계에 한 번 적용한다. 피해 배율은 방어력·저항력·보호막·피해 대리보다 먼저, 치유 배율은 최대치 제한보다 먼저 적용한다. 비용 배율은 고정·최대 비율·현재 비율 비용 계산 뒤 적용한다. 쿨타임 배율은 초를 전투 틱으로 변환할 때 적용한다.

아군은 팀 하나만 선택하고 개별 캐릭터를 추가하지 않았을 때만 그 팀의 규칙을 사용한다. 여러 팀 또는 개별 캐릭터를 섞으면 규칙 충돌을 피하기 위해 네 값 모두 100%를 사용한다. 팀 대 팀의 적군은 선택한 적 팀 규칙을 사용하며 몬스터전의 적군은 기본값을 사용한다.

팀의 `synergyRules`는 진영 또는 계열, 필요 인원, 네 전투 배율을 가진다. 선봉과 예비대를 포함한 저장 팀원 수를 검사하고 충족된 모든 규칙을 기본 전투 규칙에 곱한다. 예를 들어 기본 피해 120%에 활성 시너지 피해 110%가 있으면 최종 피해는 132%다. 같은 기준의 여러 단계도 각각 규칙으로 등록할 수 있다. 현재 대상 진영별 피해·치유 변경과 규칙 우선순위는 지원하지 않는다.

`override_rule.ruleOverride.disabledSkillIds`에는 규칙이 유지되는 동안 대상이 사용할 수 없는 스킬 ID를 저장한다. 액티브 선택, 패시브 발동, 기본 공격과 회복, 장비 연결 공격, 런타임 복제본의 원본 ID를 모두 검사한다. 이미 해당 스킬을 시전 또는 채널링 중이면 규칙 적용 시 중단하며, 규칙이 만료되면 남은 기존 쿨타임을 유지한 채 다시 사용할 수 있다. 여러 규칙의 금지 목록은 합집합으로 처리한다.

`ruleOverride.disableAllSkills`를 `true`로 설정하면 ID 목록과 관계없이 대상의 모든 스킬을 금지한다. 기본 공격·기본 회복, 장비 연결 공격, 규칙 적용 뒤 생성된 복제본도 차단한다. 여러 런타임 규칙 중 하나라도 이 값을 사용하면 전체 금지가 유지되며, 해당 규칙이 모두 만료되거나 제거되면 다시 사용할 수 있다.

## 액티브 스킬 복제

`copy_skill` 액션은 같은 진영 캐릭터가 장착한 액티브 스킬 하나를 시전자에게 전투 중 복제한다.

| 필드 | 의미 |
| --- | --- |
| `target` | `ally` 고정 |
| `copySourceIndex` | 대상의 복제 가능한 액티브 중 순번. 1~4 |
| `copySlot` | 시전자의 복제 슬롯. 1~4 |

복제 후보 순서는 대상의 `skillIds` 저장 순서다. 패시브, 베이직, 미지원 액션이 있는 스킬, 다른 `copy_skill` 스킬은 후보에서 제외한다. 대상이 전투 진입 또는 부활 대기 중이어도 복제할 수 있으며 소환수와 시전자 자신은 대상에서 제외한다. 해당 순번의 액티브가 있는 첫 아군을 자동으로 선택한다.

```json
{
  "type": "copy_skill",
  "target": "ally",
  "copySourceIndex": 1,
  "copySlot": 1
}
```

복제 시점의 스킬 정의 전체를 런타임 스냅샷으로 복사한다. 원본과 다른 런타임 ID를 사용하므로 자원 비용과 쿨타임을 독립적으로 계산한다. 같은 복제 슬롯을 다시 사용하면 기존 복제본과 남은 쿨타임을 제거하고 새 복제본으로 교체한다. 원본 데이터가 이후 바뀌거나 대상이 사망해도 이미 만든 복제본은 바뀌지 않으며 다음 전투 초기화 때 모두 제거한다.

현재 대상과 스킬을 수동으로 선택하는 UI, 대기 명단에 있으나 전투 스쿼드에는 생성되지 않은 캐릭터 조회, 선택 스킬 분류, 복제 횟수 제한과 원본 변경 실시간 추적은 지원하지 않는다.

## 팀 예비대 난입

팀 편성의 `activeMemberCount`는 편성 순서 앞쪽에서 선봉으로 출전할 인원 수다. 나머지 팀원은 전투 스쿼드에 실제 대기 유닛으로 생성되어 전장 행동과 피격에서 제외된다. 선봉이 부활 횟수를 모두 소진해 영구 사망하면 편성 순서가 빠른 예비대가 빈자리에 즉시 난입한다.

진입 지연 또는 부활 대기 중인 선봉은 자리를 계속 차지하므로 예비대가 중복 투입되지 않는다. 예비대가 남아 있는 동안에는 전투 가능한 인원이 잠시 없어도 패배로 판정하지 않는다. 여러 팀이나 개별 캐릭터를 섞어 출전시키는 경우에는 전원을 선봉으로 취급한다.

`swap_reserve` 액션은 자신 또는 살아 있는 다른 아군을 현재 대기 중인 예비대와 교체한다. `reserveIndex`는 원래 팀 편성 순서로 정렬한 현재 예비대 중 몇 번째를 투입할지 지정하며 1~10 범위다. 퇴장한 유닛은 HP·자원·재사용 대기시간을 유지한 채 새로운 예비대가 되고, 다시 투입될 때 그 상태를 이어받는다. 퇴장할 때 진행 중인 시전·채널링과 지속 효과는 정리된다.

`swap_reserve`의 `duration`이 0보다 크면 시간제 교대로 처리한다. 시간이 끝나거나 투입된 예비대가 먼저 사망하면 퇴장했던 유닛이 보존된 HP·자원·재사용 대기시간으로 복귀한다. 시간제 교대로 물러난 유닛은 다른 교대의 예비대 후보에서 제외한다. `duration`이 0이면 기존처럼 영구 교대다.

`deploy_reserve` 액션은 현재 전장 인원 제한과 관계없이 지정한 예비대 한 명을 추가 투입한다. `reserveIndex`는 현재 사용 가능한 예비대 순번이고 `duration`은 증원 시간이다. 0이면 전투 종료까지 남고, 양수이면 만료될 때 살아 있는 유닛을 기존 상태 그대로 예비대로 돌려보낸다.

`revive_ally` 액션은 부활·진입 대기 중이 아니며 완전히 사망한 일반 아군 한 명을 대상으로 한다. 소환수와 예비대는 제외한다. `reviveHpPercent`·`reviveMpPercent`·`reviveStPercent`로 회복량을, `reviveInvulnerable`로 부활 직후 무적 시간을, `revivePosition`의 `death`·`start`로 복귀 위치를 지정한다. 이 액션은 유닛 자체의 자동 부활 횟수를 소비하지 않는다.

교대 액션은 스킬의 마지막 액션으로 두어야 한다. 시전자 자신이 퇴장하면 이후 액션을 실행할 수 없다. 대상 선택 UI와 별도로 전투 도중 플레이어가 수동 교대하는 조작 UI는 제공하지 않는다.

## 런타임 규칙 변경

`override_rule` 액션은 대상의 주는 피해·받는 피해·주는 치유·받는 치유·스킬 자원 비용·재사용 대기시간 배율을 일정 시간 변경한다. 주는 값은 팀 전투 규칙 배율에 곱하며, 예를 들어 팀 피해 120%와 런타임 피해 150%는 최종 180%다. 받는 치유를 0%로 설정하면 HP와 모든 자원 회복을 차단한다. 지속시간 0은 전투 종료까지 유지한다.

받는 피해 배율은 피해 대리 경로를 나눈 뒤 실제로 피해를 받는 각 유닛에게 적용하고, 그 다음 보호막·방어력·저항력을 계산한다. 따라서 보호자와 원래 대상은 각자의 받는 피해 규칙을 사용한다. 받는 치유 배율은 주는 치유 배율과 계수를 계산한 뒤 최대 자원 제한 전에 적용한다.

`ruleOverride.id`가 같은 규칙을 다시 적용하면 별도 중첩하지 않고 네 배율과 지속시간을 새 값으로 교체한다. ID가 다른 규칙은 서로 곱해서 적용한다. 유닛이 사망하거나 다음 전투가 시작되면 런타임 규칙을 제거한다. 이미 시작된 재사용 대기시간은 다시 계산하지 않으며 이후 시작되는 재사용 대기시간부터 새 배율을 사용한다.

`disableTeamSynergies`는 대상 유닛에게 활성화된 진영·계열 편성 시너지 배율만 제외하고 팀의 기본 전투 규칙은 유지한다. `disableEquipmentEffects`는 장착 아이템으로 얻은 능력치, 무기 전투 설정, 장비 연결 공격을 임시로 제거한다. 이 프로젝트에는 별도의 아이템 조합 세트 보너스가 아직 없으므로 현재 세트 금지는 장비 효과 전체를 무효화한다. 현재 HP·자원은 새 최대치를 넘을 때만 줄이고, 규칙 만료 시 같은 장비 프리셋을 다시 적용한다. 규칙 적용 중 장비 세트를 교체해도 새 세트의 장비 효과는 규칙이 끝날 때까지 비활성 상태다.

## 무기별 독립 공격

무기를 두 개 이상 장착한 캐릭터는 각 무기가 별도의 공격 주기, 시전시간, 사거리, 공격 타입과 연결 공격 스킬을 사용한다. 한 무기의 시전 또는 재사용 대기는 다른 무기와 캐릭터 액티브 스킬을 막지 않는다. 각 무기 공격은 물리 무기면 ST, 마법 무기면 MP를 개별 소비한다.

일반 양손무기가 주무기·보조무기 두 칸을 점유한 경우에는 같은 무기 하나로 계산한다. 양손 무기 단일 슬롯 규칙이나 추가 무기 슬롯으로 실제 여러 무기를 장착한 경우에만 독립 공격이 생성된다. 무기가 하나뿐인 캐릭터와 소환수·몬스터는 기존 평타 경로를 유지한다.

캐릭터의 `equipmentRules.sameTargetWeaponPenaltyPercent`는 같은 대상을 추적하는 추가 무기 하나당 각 무기 피해에서 차감할 비율이다. 예를 들어 15%이고 세 무기가 같은 대상을 공격하면 세 무기 모두 기본 피해의 70%를 준다. 계산 결과는 최소 0%로 제한하며, 다른 대상을 추적하는 무기에는 감산하지 않는다.

## 형태별 스킬 세트

`transform` 액션의 `transform.skillIds`에 액티브 스킬 ID를 지정하면 변신 중 원래 장착 액티브 목록을 해당 목록으로 교체한다. 빈 목록은 원래 액티브를 그대로 사용한다. `transform.attackSkillId`를 지정하면 단일 무기와 맨손의 기본 공격도 해당 스킬로 교체한다.

변신이 만료되거나 다른 변신으로 교체되거나 유닛이 사망하면 원래 액티브와 기본 공격으로 즉시 돌아온다. 형태별 재사용 대기시간은 같은 유닛의 `skillCooldowns`를 사용하므로 같은 스킬 ID는 형태를 오가더라도 남은 시간을 공유하고, 서로 다른 ID는 독립적으로 관리한다. 복수 무기의 장비별 연결 공격은 형태 기본 공격보다 우선한다.

## 상태·버프의 지속시간과 중첩

`add_buff`, `delete_buff`, `add_state`, `delete_state`를 편집하고 실행할 수 있다. 현재는 단일 대상이며 액션별 진영·최소/최대 사거리로 대상을 선택한다. 효과는 시전 완료 시 적용하며 별도 투사체를 만들지 않는다.

- **버프**: 공격력·마력·방어력·저항력·이동속도·사거리·공격 간격·기본 시전시간 중 한 능력치를 변경한다. 음수는 감소다. 공격 간격과 시전시간은 작을수록 빠르다. 스킬의 명시적인 `castTime`과 이미 진행 중인 시전/공격 대기시간은 바꾸지 않는다.
- **계산**: `기본 능력치 + 고정값 합계 + 기본 능력치 × 퍼센트 합계 / 100`. 모든 값에 해당 효과의 중첩 수를 곱한다. 퍼센트 효과끼리 복리로 곱하지 않는다. 공격 간격은 최소 0.1초, 사거리는 최소 1, 나머지는 최소 0이다. 마지막 효과가 사라지면 원래 값을 정확히 복구한다.
- **최종값 고정과 삭제**: 버프 계산을 `override`로 설정하면 선택 능력치를 지정한 최종값으로 고정하고 같은 능력치의 다른 가산 효과를 무시한다. 값을 0으로 설정하면 해당 능력치를 삭제하는 규칙으로 사용할 수 있다. 최종값 고정이 여러 개면 가장 나중에 적용된 효과가 우선한다.
- **능력치 전환**: `convert`는 효과를 부여하는 순간 대상의 `sourceStat` 원본값을 저장하고 그 값의 `value`%를 선택 능력치에 가산한다. 이후 원본 능력치가 변해도 전환량은 다시 계산하지 않으며, 다른 전환 결과를 원본으로 참조하지 않아 상호 전환의 순환 계산을 막는다.
- **다음 1회 스킬 보정**: `next_skill_modifier`는 다음 액티브 또는 채널링 스킬의 시전시간·실제 자원 비용·새로 시작하는 쿨타임에 각각 `nextCastTimePercent`, `nextResourceCostPercent`, `nextCooldownPercent`를 곱한다. 0% 시전시간은 즉시시전이다. 유효 대상과 비용을 확인해 스킬이 실제로 시작될 때 1회 소모하며 기본 공격·기본 회복·패시브에는 소모되지 않는다. 시전 중단이나 채널링 중단으로 끝나도 보정된 쿨타임을 적용한다. 여러 보정 효과가 있으면 각 배율을 곱하고 모두 소모한다.
- **피해 반사**: `damage_reflect`는 보호막과 HP에서 실제로 감소한 피해의 `reflectPercent`%를 공격자에게 돌려준다. `reflectScope`로 모든 피해·기본 공격·스킬 피해를 구분하고 `reflectDamageType`은 방어를 무시하는 고정 피해 또는 원래 피해 유형을 사용한다. 여러 반사는 비율을 합산한다. 피해 대리 수신자는 자신이 실제로 받은 몫만 반사하며, 반사 피해에는 다시 반사를 적용하지 않아 무한 루프를 막는다.
- **상태**: 기절은 행동·자발적 이동을 막고 진행 중인 시전을 취소한다. 이동 불가는 자발적 이동과 이동 액션을 막지만 공격·시전은 허용한다. 침묵은 장착 스킬의 사용을 막고 진행 중인 장착 스킬 시전을 취소하며 기본 공격·기본 회복은 허용한다. 충돌로 밀리는 것은 차단하지 않는다.
- **시전 취소**: 이미 지불한 자원은 환불하지 않으며 취소된 스킬은 쿨타임, 기본 행동은 공격 대기시간에 들어간다. 이미 발사된 투사체는 남는다.
- **효과 ID**: 대상별로 `종류 + 효과 ID + 시전자`가 같으면 하나의 인스턴스다. 다른 시전자의 효과는 독립적으로 유지한다. 다른 효과를 만들 때는 다른 ID를 사용해야 한다.
- **재적용**: 시간 갱신은 1중첩을 유지한다. 중첩 증가는 최대 중첩(1~20)까지 더하고 전체 중첩의 공통 지속시간을 갱신한다. 상한에서도 시간은 갱신된다. 상태 중첩은 기절 강도 등을 곱하지 않는다.
- **시간**: 초 단위이며 60 전투 틱/초로 만료한다. 배속·즉시 결과 계산에도 같은 규칙을 사용한다. 0은 전투 종료까지 유지한다. 사망·종료·중단·다음 전투 초기화 시 효과를 정리한다.
- **해제**: 제거 액션은 ID·분류·전체 방식과 효과 성격 조건에 맞는, 같은 종류의 해제 가능한 인스턴스를 모든 시전자에 대해 지운다. 실제 해제할 효과가 있는 대상만 선택한다.
- **표시**: 전장 유닛 아래에 이름·중첩·남은 시간을 표시하고 적용·해제·만료 로그를 남긴다. 런타임 인스턴스는 캐릭터/몬스터 원본 데이터에 저장하지 않는다.

기본값은 지속 5초, 시간 갱신, 최대 1중첩이다. 버프 기본값은 공격력 +10, 상태 기본값은 기절이다. 기존에 `effect`가 없거나 미지원 상태(은신·탑승 등)를 지정한 액션은 원본을 보존하며 실행을 잠근다. 편집기의 **기본 효과 설정으로 교체**로 명시적으로 바꾼 뒤 저장한다.

```json
{
  "type": "add_buff",
  "target": "ally",
  "duration": 5,
  "effect": {
    "id": "attack_up",
    "name": "공격력 증가",
    "stat": "atk",
    "mode": "flat",
    "value": 10,
    "stackMode": "stack",
    "maxStacks": 3
  }
}
```

상태는 `effect.state`에 `stun`, `root`, `silence`를 사용한다. 주기 효과 전용 상태는 `periodic`이다. 상태·버프 추가와 해제 액션에도 `area`·`areaCenter`·`maxTargets`를 설정해 원형 범위로 적용할 수 있다. 광역 해제의 최대 대상 수는 실제로 해제 조건과 일치하는 유닛만 계산한다. 해제 분류·면역과 이벤트 기반 패시브는 아래 규칙을 따른다.

### 해제 분류와 면역

효과 추가 액션에서 `effect.category`를 일반(`general`)·물리(`physical`)·마법(`magic`)으로, `polarity`를 이로운(`beneficial`)·해로운(`harmful`) 효과로 설정한다. 이는 효과 부여/해제 분류이며 주기 피해의 물리·마법 피해 계산 타입과 별개다. 기본값은 일반·해제 가능(`dispellable: true`)이며 상태는 해로운 효과, 버프는 이로운 효과다. 음수 능력치나 주기 피해를 버프로 만들 때 해로운 성격을 직접 지정해야 한다.

제거 액션의 `effect.dispelMode`는 ID(`id`, 기존 기본값), 분류(`category`), 전체(`all`) 중 선택한다. 분류 방식은 `dispelCategory`를 사용한다. `dispelPolarity`는 전체(`any`, 기본값), 이로운 효과만, 해로운 효과만을 지원한다. ID 방식만 ID가 필수다. `delete_state`는 상태만, `delete_buff`는 버프만 대상으로 하며 두 종류를 함께 제거하려면 액션을 두 개 넣는다. 일치하는 모든 시전자의 전체 중첩을 제거한다. `dispellable: false`는 ID 해제와 전체 해제를 포함한 모든 해제를 막지만 자연 만료·사망·전투 정리는 막지 않는다.

버프의 면역 범위에서 상태(`state`), 해로운 효과(`harmful`), 모든 상태·버프(`all`)를 선택한다. `effect.immunity.category`는 모든 분류(`all`) 또는 하나의 분류이며, `state`는 상태 제한 없음(`all`) 또는 특정 상태다. 범위·분류·상태 조건을 **모두** 만족하는 새 부여를 차단한다. 특정 상태를 지정하면 버프는 차단하지 않는다. 면역 전용 버프는 `effect.mode: "immunity"`로 설정하고, 능력치 변경과 함께 적용하려면 기존 가산 계산을 유지한다.

- 면역은 기존 효과를 없애거나 이미 적용 중인 주기 피해를 멈추지 않는다. 새 효과 부여와 갱신·중첩만 차단한다. 직접 피해·회복·이동·소환을 막는 무적 기능은 아니다.
- 면역 부여 전 기존 효과를 정리하려면 제거 액션을 먼저 둔다. 면역은 해제 액션 자체를 막지 않는다.
- 면역도 일반 버프이므로 지속시간·해제 가능 설정을 따른다. 같은 시전자의 같은 면역 버프 ID 갱신은 자기 자신에게 막히지 않지만, 다른 면역 인스턴스는 검사한다. 면역 제거/만료 후에는 새 부여가 가능하다.
- 면역 판정은 부여 시점에 수행하며 차단 로그를 남긴다. 이미 지불한 스킬 비용·쿨타임은 환불하지 않고 다른 액션은 계속 실행한다.

예: 마법 분류의 기절만 막는 버프의 효과 설정:

```json
{
  "id": "magic_stun_ward", "name": "마법 기절 면역",
  "mode": "immunity", "category": "magic", "polarity": "beneficial", "dispellable": true,
  "immunity": { "scope": "state", "category": "magic", "state": "stun" },
  "stackMode": "refresh", "maxStacks": 1
}
```

### 주기 피해·회복

상태·버프 추가 액션에서 **주기 효과**를 피해 또는 회복으로 선택한다. 기본 간격은 1초, 회당 수치는 10이며 기존 효과에는 주기 효과가 없다. 능력치·행동 제한 없이 주기 효과만 적용하려면 상태 종류(`effect.state`) 또는 버프 계산(`effect.mode`)을 `periodic`으로 선택한다. 일반 상태·능력치 버프와 주기 효과를 함께 적용하는 것도 가능하다.

`effect.periodic`의 필드는 `type`(`damage`/`heal`), `interval`(초), `value`(중첩당 고정 수치), `damageType`(`physical`/`magic`/`fixed`), `resource`(`HP`/`MP`/`ST`/`BP`)다. 피해에는 피해 타입, 회복에는 자원을 사용한다. 간격은 양수, 수치는 0 이상이어야 하며 잘못된 설정은 실행을 잠근다. 간격은 60틱/초 기준으로 올림하고 최소 1틱이다.

- 최초 적용은 부여 후 한 간격 뒤다. 1초 간격·3초 지속이면 1·2·3초에 총 세 번 적용한 후 만료한다. 지속시간이 간격보다 짧으면 적용 없이 만료한다. 지속시간 0은 해제 또는 전투 종료까지 반복한다.
- 갱신·중첩은 다음 적용까지 남은 틱을 유지한다. 간격을 바꿔 재부여하면 새 간격부터 센다. 회당 수치는 현재 중첩 수에 비례하며, 새 설정으로 재부여하면 해당 인스턴스의 수치도 갱신된다.
- 주기 피해는 당시의 방어력·저항력·보호막 규칙을 적용하고 최초 시전자의 피해 기록에 집계한다. 회복은 자원 상한과 기존 보호막 부여 규칙을 따르며 최초 시전자의 회복량에 집계한다. 회당 수치는 능력치 계수가 아닌 고정값이다.
- 시전자가 사망해도 이미 부여한 효과는 남는다. 대상이 사망하면 중단하고 효과를 제거한다. 죽은 대상을 회복하거나 부활시키지 않는다. 해제·전투 종료·재시작 시 추가 적용도 중단된다.
- 주기 피해는 상태로 만들면 `delete_state`, 버프로 만들면 `delete_buff`로 같은 ID를 해제한다. 별도의 주기 효과 해제 액션은 없다. 효과를 반복 부여할 때만 스킬 비용을 지불하며 매 주기마다 자원·쿨타임을 소모하지 않는다.

예: `effect.state: "periodic"`인 상태에 다음 설정을 넣으면 1초마다 중첩당 마법 피해 10을 준다.

```json
"periodic": { "type": "damage", "interval": 1, "value": 10, "damageType": "magic", "resource": "HP" }
```

## 전투 이벤트

전투 화면 → 전투 로그 → **전투 이벤트 상세**에서 적중·피격·치유·사망과 시전 시작·완료·중단을 종류별로 확인한다. 한 전투의 최근 1,000건을 메모리에 보관하며 화면에는 필터에 맞는 최근 200건을 표시한다. 전투 종료 시 최근 1,000건을 전투 기록 JSON에 스냅샷으로 저장하며 전투 기록 화면의 **상세 이벤트**에서 시간·종류·출처·대상·스킬·수치·사유를 펼쳐 볼 수 있다. 새 전투 시작·초기화 시 메모리 이벤트만 비운다.

| 이벤트 | 발생 기준 |
| --- | --- |
| `cast_start` | 지원되는 시전을 실제 시작할 때. 즉시시전도 포함 |
| `cast_complete` | 시전 대기가 완료되어 효과 실행에 들어갈 때. 투사체 명중과는 별개 |
| `cast_interrupt` | 기절·침묵 또는 사망으로 진행 중인 시전을 취소할 때 |
| `hit` / `damaged` | 살아 있는 대상에게 피해 액션을 적용할 때 각각 한 번. 광역·연쇄는 대상마다 발생 |
| `heal` | HP/MP/ST/BP가 실제로 증가할 때. 증가량 0은 제외 |
| `death` | 살아 있던 개체의 HP가 0이 되는 순간 한 번. 소환 수명 종료도 별도 사유로 포함 |

피해 이벤트는 적중 → 피격 순서이며, 치명적 피해면 시전 중단(해당 시) → 사망이 이어진다. 이벤트 전달 전에 피해·생사 상태를 확정한다. 시전 완료 후 유효 대상이 사라져도 완료 이벤트는 남고 적중은 발생하지 않는다.

`amount`는 실제 자원 변화량이다. 피해는 `hpDamage`와 `barrierDamage`로 분리하며 초과 피해를 제외한다. 기존 DPS 집계 방식은 변경하지 않는다. `periodic`으로 주기 효과를 구분하고 최초 시전자를 출처로 기록한다. 이벤트의 `source`는 행동 원인, `target`은 대상이며, 피격·사망에서도 공격자/피해자 순서를 유지한다. 환경에 의한 사망은 출처가 없다. 시각은 60틱/초 전투 틱 기준이다.

엔진에서는 `subscribeBattleEvent(type, callback)`으로 구독하고 반환된 함수로 구독을 해제한다. `*`는 전체 이벤트다. 콜백 첫 인자는 변경 불가능한 이름·유닛 ID·진영·스킬 ID·수치 등의 스냅샷이고, 두 번째 인자는 전투 유닛 참조 `{source,target}`다. 조회용 `getBattleEvents(type)`는 원본 유닛 참조를 포함하지 않는다. 미리보기 전투는 기록과 구독 알림에서 제외한다.

중첩 이벤트는 큐로 전달하며 깊이 8, 한 연속 처리 128건을 상한으로 둔다. 구독자 하나가 예외를 내도 다른 구독자는 계속 처리한다. 패시브는 아래 규칙으로 이벤트를 구독한다.

### 이벤트 기반 패시브

스킬 수정 창에서 슬롯을 **패시브**로 선택하고 발동 조건·확률·주기 효과 포함 여부를 설정한다. 캐릭터와 몬스터의 사용 스킬 목록에 장착하면 실행된다. 무기의 기본 공격 대체 슬롯에는 패시브를 지정할 수 없다. 기존에 잘못 연결된 패시브 무기는 기본 공격으로 대체한다.

- 조건: 자신의 적중(`hit`), 피격(`damaged`), 시전 완료(`cast_complete`), 회복(`heal`), 적 처치(`kill`). 시전 완료는 기본 공격/회복도 포함하며 명중 여부와는 별개다. 피해·회복량 0은 발동하지 않는다. 처치는 반대 진영을 HP 피해로 죽였을 때만 인정하며 소환 수명 종료는 제외한다.
- 발동 확률 기본값은 100%, 주기 효과 포함은 꺼짐이다. 기존 조건 없는 패시브는 자동 활성화하지 않고 조건 설정 필요로 표시한다. 0%는 발동하지 않으며, 설정은 저장 후 다시 편집할 수 있다.
- 이벤트 당 유효 대상·자원·쿨타임을 검사한 뒤 확률을 판정한다. 성공하면 공통 자원을 한 번 지불하고 공통 쿨타임을 시작한다. 쿨타임 0도 동일 패시브는 한 전투 틱에 한 번만 발동한다. 중복 장착 ID는 한 번만 처리한다.
- 시전시간은 적용하지 않고 액션을 즉시 실행한다. 진행 중인 기본 행동의 시전·대기시간은 덮어쓰지 않는다. 다만 패시브 자체의 상태/이동 효과로 영향을 주는 것은 가능하다. 상태에 의한 행동 차단과 달리 패시브는 기절·침묵 중에도 발동한다. 죽은 소유자는 발동하지 않으므로 치명적 피격을 사후 회복으로 되돌리지 않는다.
- 피격 시에는 공격자, 나머지는 이벤트 대상을 우선 후보로 삼고 각 액션의 기존 대상·사거리 검증을 적용한다. 유효하지 않으면 다른 후보를 찾으며, 자신 대상은 자신에게 적용한다. 처치 후 회복은 자신/아군 대상으로 설정한다.
- 패시브 효과는 다른 패시브를 발동시키지 않는다. 지연된 주기 효과에도 이 표식을 유지한다. 일반 액티브/기본 행동의 주기 효과는 ‘주기 효과 포함’을 켠 패시브만 발동시킨다. 추가타/반사는 현재 고정 액션 수치로 구성하며, 받은 피해 비율 반사 등 이벤트 수치 계수는 아직 없다.
- 전투 로그에 패시브 발동을 표시하고 상세 이벤트에는 `(패시브)`를 표시한다. 소환수의 별도 스킬 장착, 사망한 소유자의 사망 시 패시브, 아군/적 전체 관찰 조건은 아직 없다.

```json
{
  "slot": "passive",
  "cooldown": 1,
  "passiveTrigger": { "event": "damaged", "chance": 100, "includePeriodic": false }
}
```

## 예제와 검증

### 편집기 지원 상태

- 실행 지원 액션은 피해, 회복, 자원 감소, 이동(Dash·Teleport·Knockback·Pull·Push), 소환, 지속 필드, 변신, 스킬 복제, 부활, 예비대 증원·교대, 장비 세트 교체, 전투 규칙 변경, 설정된 상태·버프의 추가/제거다.
- 기존 미지원 액션과 알 수 없는 액션은 원본 필드를 유지하여 표시한다. 지원 액션으로 교체하거나 삭제한 뒤 저장할 수 있다. 미지원 액션이 하나라도 있는 스킬은 전체를 전투에서 제외하므로 일부 효과만 실행되거나 자원만 소모되지 않는다.
- 캐릭터·몬스터·무기 스킬 선택에도 미지원 상태를 표시한다. 이미 지정된 미지원 무기 스킬은 전투에서 유닛의 기본 공격으로 대체한다.
- 액션별 대상·최소 거리·최대 대상 수·광역·연쇄, 조건과 대상별 쿨타임, 실행 결과 계수, 상태/버프·주기 효과·해제 분류·면역, 전투 이벤트와 패시브, 채널링을 지원한다.

마력 폭발, 치유의 파동, 회전베기, 아마겟돈, 야수 소환, 노포설치, 치유 정령 소환을 추가했다. 모두 편집 가능한 초기 수치다.

`node --test tests/skill-engine.test.cjs`로 시전 대기/즉시시전, 광역 진영·반경·대상 제한, 소환 한도·수명·공격·기록, 데이터 정규화를 검증한다.
