# 아이템 관리와 장비 보정

2026-10-11 구현. 기존 사용자 아이템·캐릭터·스킬 JSON을 일괄 변환하지 않습니다.

## 기존 구조와 화면

아이템은 `data/items.json`의 평면 능력치와 카테고리·슬롯·`attackSkillId`를 사용합니다. 무기의 사정거리·공격속도·시전속도·착용 방식은 기존 `applyWeaponCategoryStats`가 카테고리 설정으로 결정합니다. 기존 능력치 공식도 유지합니다.

목록은 이름 → 착용방식 → 공격력 → 마력 → 방어력 → 저항력 → 사정거리 → 작동스킬 → 부가 능력치 → 수정의 10열입니다. 이름에는 기존 공용 카테고리 아이콘 또는 텍스트 fallback을 사용합니다. 카테고리는 표에서만 숨기며 수정 창 설정·데이터·슬롯 필터는 유지합니다. 능력치 0은 `-`로 표시하지만 숫자 0으로 정렬합니다.

헤더와 본문 모두 이름·부가 능력치는 왼쪽, 나머지는 가운데 정렬합니다. 이름 18%, 부가 능력치 28%, 작동스킬 12%, 착용방식 7%, 각 숫자 6%, 수정 5%로 배분합니다. 36px 아이콘과 8px 간격·기존 행 높이를 유지하며 최소 표 너비는 1060px입니다. 정렬 화살표는 제목의 중심선을 밀지 않도록 별도 배치합니다.

수정 이외의 모든 열은 첫 클릭 오름차순, 다음 클릭 내림차순이며 화살표와 `aria-sort`를 제공합니다. 숫자 5열은 숫자, 나머지는 한국어 표시 문자열로 비교합니다. 부가 능력치는 전체 설명 문자열 기준입니다. 슬롯 필터를 적용한 복사 목록만 정렬하여 원본 순서와 수정 인덱스를 보존합니다. 좁은 화면에서는 표 내부를 스크롤합니다.

HP/MP/ST/이동속도/공격속도/시전속도·스탯 보정의 0이 아닌 항목을 최대 2개와 나머지 개수로 요약하고 스킬 보조 개수를 별도 표시합니다. 클릭하면 전체 설명이 펼쳐집니다. 무기의 속도는 기존 카테고리 값이며 가산 속도 보정으로 변경한 것이 아닙니다.

수정 창은 기본 정보, 주 능력치, 부가 능력치, 스탯 보정, 스킬 보조로 나뉩니다. 데스크톱 2열·모바일 1열이며 입력 영역만 스크롤하고 취소·저장·삭제는 하단에 유지합니다. `작동스킬`은 기존 무기 기본 공격 연결의 UI 명칭입니다. 비무기에 새로운 자동 발동 규칙을 추가하지 않습니다.

## 스탯 보정

목록은 스탯 관리의 `CHARACTER_STAT_DEFS`를 사용합니다. 현재 힘/체력/민첩/집중/지능/지혜 6종이며 0으로 바꿔 보정을 제거합니다.

```json
{"statModifiers":{"str":5,"focus":3}}
```

0이 아닌 유한한 값만 저장하고 누락 필드는 빈 보정입니다. 저장된 캐릭터 `attributes`는 배분한 원본을 유지합니다. `getCharacterEffectiveAttributes`는 원본과 현재 장비를 매번 새로 합산하며 최종값은 0 이상입니다. 장비 보정에는 배분 UI의 포인트·5단위 제한을 적용하지 않습니다. 유효 스탯을 기존 `getStatAbilityBonus`와 전투 유닛 `attributes`에 전달하여 스탯 계수에도 적용합니다. 스탯 정의를 추가할 때 기존 능력치 공식의 지원 범위는 그대로 따릅니다.

기존 장비 합산과 동일하게 여러 장비 값을 더하고 양손 아이템 ID는 한 번만 셉니다. 반복 장착/해제·재계산으로 누적되지 않습니다.

## 스킬 보조

실제 `skillsJson`에서 실행 가능한 스킬과 대상 액션·계수 또는 자원 행을 선택합니다. 사용자 정의 기본/액티브/패시브 스킬을 지원합니다. 자동 생성되는 내장 기본 공격·기본 회복은 선택 목록에서 제외합니다. 필요하면 명시적인 스킬을 생성해 작동스킬로 연결합니다.

```json
{"skillModifiers":[{"skillId":"skill_id","target":"actions.0.coefficients.1.value","signature":"해당 정규화 액션의 JSON 문자열","value":0.2}]}
```

`target`은 임의 경로 실행용이 아닙니다. `getItemSkillTargets`의 허용 대상과 서명이 모두 일치해야 적용됩니다.

| 항목 | 실제 대상과 단위 |
| --- | --- |
| 계수 | 피해/회복/자원 감소 액션과 해당 필드 효과의 선택한 `coefficients[n].value`. 고정값 또는 기존 % 계수 단위 |
| 재사용 대기시간 | 스킬 `cooldown`, 초 |
| 지속시간 | 버프/상태/필드/소환/변신/규칙 액션 `duration`, 필드 효과 `fieldEffectDuration`, 활성 채널링 `channel.duration`; 초 |
| 자원 소모 | 선택한 `resourceCosts[n].value`. HP/MP/ST/BP/사용자 자원과 고정·최대/현재 % 방식 구분 |
| 범위 | 사용자 지정 액션 `rangeValue`, 피해/회복/자원 감소 `area`, 필드 `fieldRadius`; 기존 전장 범위 단위 |

선택한 수치의 단위로 가산합니다. 기존 150% 계수에 `+0.2`는 150.2%이며 +20%p를 원하면 `+20`입니다. 감소는 음수로 입력합니다. 같은 대상의 여러 장비/행을 합산한 뒤 쿨타임·비용·범위·지속시간을 0 이상으로 제한합니다. 계수는 기존처럼 부호를 유지합니다. 기존 팀 배율·다음 스킬 배율과 피해 계산은 이후 기존 경로로 처리합니다.

액션과 자원 행은 JSON 서명을 저장합니다. 원본 액션의 순서·내용 또는 자원 행이 변경되면 보정을 미적용으로 표시하고 재선택/삭제를 안내합니다. 액션 ID가 없는 현재 스키마에서 다른 효과를 잘못 보정하는 일을 방지합니다.

`getRuntimeItemSkill`은 원본을 수정하지 않고 유닛별 복사본을 만듭니다. 활성·작동스킬·독립 무기·패시브 경로가 사용합니다. 세트별 유효 스탯과 보조를 전투 시작 때 스냅샷하며 세트 교체/장비 효과 무효화·복원에도 함께 교체합니다. 시전·투사체·필드는 기존대로 실행 시점 복사본을 유지합니다. 관리 화면 장비 변경은 다음 전투 유닛 생성에 반영하며 진행 중인 효과를 소급 수정하지 않습니다.

## 삭제와 저장

체크박스·선택 삭제를 제거하고 기존 캐릭터/Entity 편집과 같은 브라우저 확인창을 사용합니다. 삭제 버튼은 수정 창에만 나타나며 이름과 장착 캐릭터를 확인합니다.

아이템 ID 참조는 캐릭터의 현재 `equipment`와 모든 `equipmentSets[].equipment`입니다. 기존 정책대로 모든 세트에서 해제합니다. 최신 캐릭터를 읽어 참조 해제를 먼저 저장한 뒤 아이템을 삭제합니다. 참조 저장 실패 시 아이템을 유지합니다. 아이템 저장 실패 시 아이템은 유지하지만 해제가 먼저 저장됐을 수 있어 안내합니다. 두 API는 원자적 트랜잭션이 아니며 동시 편집 충돌 제어도 기존과 동일합니다.

아이템 API 저장 실패는 호출자에게 전달하고 성공 전에 브라우저 캐시를 덮어쓰지 않습니다. 마지막 아이템을 삭제한 빈 배열도 유지합니다.

- 표 표시 후속 수정은 관련 브라우저 2개 테스트를 실행했습니다. 헤더/본문 정렬, 아이콘·텍스트 세로 중심, 펼치기, 숫자 정렬·필터, 수정 창과 카테고리 유지, 1920/1440px 표 가로 넘침 없음 및 640px 스크린샷을 확인했습니다. 데이터·전투 로직 변경은 없습니다.

- 1920/1440/640px 목록, 1440/640px 수정 창 스크린샷을 검수했습니다. 사용자 원본 대신 복사본으로 테스트합니다.
