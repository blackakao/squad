# 이미지 생성 오류 확인

## 2026-10-07 버튼 동작 및 저장 이름 수정 재개

- 10월 5일 중단 전에 적용한 수정: 생성 폼의 브라우저 자동 검증 대신 제시어·크기·시드를 코드에서 검사하고 버튼 아래 상태 영역에 안내합니다. 자동 검증이 상단 입력칸으로 초점을 옮기는 경로를 제거했습니다.
- 처리 중 버튼 문구를 바꾸지 않고 재생성 시작 시 미리보기를 지우지 않아 불필요한 배치 변경을 줄였습니다. 생성·저장 중 중복 실행도 차단합니다.
- 서버의 기존 영문 전용 파일명 정리가 한글 이름을 제거하던 문제를 수정했습니다. 생성 이미지에만 한글·공백·대소문자를 보존하며 이미지 확장자를 중복하지 않습니다. 금지 문자 치환, Windows 예약 이름 보정, 이름 길이 제한을 적용합니다. 같은 이름은 번호를 붙여 배타 생성하고 기존 파일을 덮어쓰지 않습니다.
- 기존 초상화·아이콘 등 다른 이미지 종류는 날짜를 붙이는 기존 파일명 규칙을 유지합니다. 데이터 이미지 업로드와 URL 이미지 업로드가 같은 저장 함수를 사용합니다.
- 서버 재시작과 브라우저 새로고침이 필요합니다. 사용자 데이터·기존 생성 이미지는 변경하지 않았습니다.
- 검증: Node 회귀 테스트 8개 통과. 파일명·중복 보존·경로 제한 테스트 통과. 실제 외부 AI 호출은 모의 처리하며, 브라우저 도구 연결 실패로 수정 후 실화면의 첫 클릭/스크롤 동작은 아직 미검증입니다. 저장 버튼 첫 클릭 누락은 기존 조사에서도 재현되지 않았으므로 완전 해결로 단정하지 않습니다.

## 내 스타일 관리

이미지 생성 페이지의 스타일 세팅 아래에서 이름을 붙여 여러 스타일을 관리합니다.

1. 스타일 세팅과 이름(1~80자)을 입력하고 **새 스타일로 저장**을 누릅니다. 기본 프리셋을 적용한 내용도 저장할 수 있습니다.
2. 저장된 스타일을 선택하고 **불러오기**를 누르면 스타일 세팅에 적용되고 그림 스타일은 직접 입력으로 바뀝니다. 선택만으로 내용이 바뀌지는 않습니다.
3. 이름과 스타일 세팅을 편집한 뒤 **선택 스타일 수정**을 누르면 선택 항목을 갱신합니다. 다른 이름으로 **새 스타일로 저장**하면 복사본을 만듭니다.
4. **삭제**는 확인 후 목록에서 제거합니다. 현재 입력한 스타일 세팅은 유지합니다.

이름 중복·빈 이름·빈 스타일 문장은 저장하지 않습니다. 목록 조회 실패 시 저장을 막고 목록 새로고침으로 복구합니다. 저장 실패 시 기존 목록과 편집 내용을 유지합니다. 이름은 HTML이 아닌 텍스트로 표시합니다.

목록은 `GET/PUT /api/image-styles`와 `data/image-styles.json` 배열을 사용합니다. 파일이 없으면 빈 목록이며 최초 저장 시 생성됩니다. 각 항목은 `id`(UUID), `name`, `stylePrompt`, `updatedAt`(ISO 시각)을 포함합니다. 기존 마지막 생성 설정 및 기본 프리셋과 독립적이며 제시어·AI·모델·크기·시드를 저장하거나 불러오지 않습니다. 여러 브라우저에서 동시에 수정하면 마지막 저장이 적용되므로 수정 전에 목록 새로고침을 사용하세요.

검증: 이미지 생성 Node 테스트 총 6개 통과. 실제 Python 서버에서 브라우저로 저장 → 새로고침 → 불러오기 → 이름·내용 수정 → 새로고침 후 복원 → 삭제를 확인했습니다. 테스트 항목은 삭제했습니다. 게임 데이터 자동 이전을 피하기 위해 테스트 탭에서 앱 전체 초기화만 차단하고 이미지 생성 화면과 실제 저장 API를 사용했습니다.

## 2026-10-05 확인 및 수정

- 저장된 설정은 Puter이고 모델은 빈 값이었습니다. 기존 코드가 기본값으로 보내던 `gpt-image-1-mini`는 [Puter 공식 문서](https://docs.puter.com/AI/txt2img/)에서 제공 종료 및 `Model not found` 대상으로 안내합니다.
- 기본 모델을 문서에 안내된 `gpt-image-2`로 변경했습니다. 직접 지정한 모델은 유지하고, OpenAI 제공자 강제 지정을 제거해 Puter의 모델별 제공자 선택을 사용합니다.
- 중첩된 `error.message`도 화면에 표시합니다. 서버가 HTML을 반환하면 JSON 파싱 오류 대신 서버 재시작 안내를 표시합니다.
- 다른 제공자에서 생성한 뒤 Puter 사용량을 조회하지 않습니다. Puter 생성 후에는 로그인 상태에서만 사용량을 조회합니다.

## 실패 시 확인

- Puter `Model not found`: 모델 입력을 비우거나 현재 지원 모델을 입력합니다. 이전 모델이 직접 저장되어 있다면 자동 교체하지 않으므로 사용자가 변경해야 합니다.
- Puter SDK 로드 실패: 인터넷 연결과 `https://js.puter.com/v2/` 접근을 확인합니다.
- Puter 인증·사용량 오류: 로그인 및 계정 잔액/사용 한도를 확인합니다. 모델 변경으로 계정 제한이 해소되지는 않습니다.
- 서버가 JSON 대신 HTML 반환: 프로젝트의 Python 서버로 접속하고 최신 코드로 재시작합니다.
- Hugging Face: 서버 프로세스의 `HF_TOKEN`, 모델 접근 권한과 제공 상태를 확인합니다.
- Pollinations/Hugging Face의 실제 외부 서비스 연동은 이번에 검증하지 않았습니다. 서버에 남아 있는 기존 엔드포인트의 현재 지원 여부는 별도 확인이 필요합니다.
