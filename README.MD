# Squad Auto Battle Prototype

관전형 자동전투 RPG를 실험하는 정적 HTML/CSS/JavaScript 앱입니다. Python 서버로 실행하며, 캐릭터·팀·장비·스킬 조합의 자동 전투 결과를 관찰합니다.

처음 실행할 때는 아래 실행 방법을, 개발을 재개할 때는 [작업 재개 메모](docs/resume.md)와 [에이전트 작업 규칙](AGENTS.md)을 먼저 확인합니다. 전체 구현 요약은 [프로젝트 개요](docs/project_overview.md), 파일과 모듈 관계는 [아키텍처](docs/architecture.md), 저장 형식은 [데이터 구조](docs/data_structure.md)를 기준으로 확인합니다.

## 독립 3D CharacterViewer

메인 메뉴의 **3D 캐릭터 제작**에서 CharacterViewer로 바로 이동합니다. 새로 추가한 **대머리 블랭크 얼굴 남자/여자** GLB는 뷰어의 **남성 블랭크 · 머리/눈**, **여성 블랭크 · 머리/눈** 버튼으로 불러옵니다. 원본 리그와 애니메이션을 유지하면서 Head 본에 독립 가발 10종씩과 눈 10종을 런타임으로 조합합니다. 블랭크 모델에서는 이번 단계 범위인 머리와 눈 선택만 표시합니다. 머리 스타일과 8가지 머리 색상은 각각 선택하며, 다른 파츠를 바꿔도 현재 선택이 유지됩니다.

외부 남녀 SD 모델은 뷰어의 **남성 SD · 외형/무기**, **여성 SD · 외형/무기** 버튼으로 불러옵니다. 각 모델에 맞는 머리·피부색·눈·코·귀·입 10종의 변형과 손에 따라 움직이는 무기 장착 지점을 추가했습니다. [외부 모델 사용법과 지원 범위](docs/IMPORTED_SD_MODELS.md)를 참고하세요.

CharacterViewer의 외형 조합기는 공통 SD 베이스에서도 남성형 머리 10종·여성형 머리 10종, 눈 10종, 코 5종, 입 10종, 피부색 5종을 조합할 수 있습니다. 무작위 조합·부품 잠금·조합 저장·512×512 PNG 다운로드를 지원합니다. [외형·초상화 조합 안내](docs/PORTRAIT_COMPOSER.md)와 [현재 기본 모델](docs/IMPORTED_SD_MODELS.md)을 참고하세요.

공통 베이스의 Walk/Run은 정면(+Z) 이동 주기를 사용하며, Knockdown은 넘어지기, Death는 누운 자세 유지로 구분됩니다. 뷰어의 **장비 테스트**에서 투구·갑옷·장갑·부츠·검/창·방패를 Head·Spine·양손·양발 본에 장착할 수 있습니다. 장비 선택은 외형 조합 프리셋에 함께 저장되지만 게임의 장비 데이터·능력치는 변경하지 않습니다.

`python server.py` 실행 후 `http://127.0.0.1:8000/character-viewer.html`에서 SD 인간형 GLB/glTF 개발용 뷰어를 엽니다. 기존 게임과 독립되어 모델 로딩, 전체 보기, 회전·줌, 실제 AnimationClip 목록과 재생/정지/반복/속도, 모델·텍스처·본 정보를 확인할 수 있습니다. Three.js 0.180.0은 로컬 배포 파일로 포함되어 별도 npm 설치나 빌드는 필요하지 않습니다.

[공통 SD 베이스 v1](assets/characters/base/human_sd_base_v1.glb)을 포함합니다. [샘플 뷰어](http://127.0.0.1:8000/character-viewer.html?model=assets/characters/base/human_sd_base_v1.glb)에서 실제 스킨과 9개 기본 클립을 확인할 수 있습니다. [베이스 모델 제작·보정 안내](docs/SD_BASE_MODEL.md)를 참고하세요. 다른 GLB는 [모델 폴더](assets/characters/models/)에 넣거나 로컬 파일로 선택할 수 있습니다. glTF는 BIN·텍스처 상대 경로를 유지하여 서버 경로로 불러옵니다. [CharacterViewer 사용법과 공통 리그/애셋 규격](docs/CHARACTER_VIEWER.md)을 참고하세요.

관전형 자동전투 RPG를 실험하기 위한 웹 프로토타입입니다. 플레이어가 전투 중 직접 조작하지 않고, 미리 구성한 캐릭터, 팀, 장비, 스킬 조합이 자동 전투 결과를 만드는 구조를 검증합니다.

현재 구현은 10인 이하 스쿼드 전투, 캐릭터/몬스터/팀/진영/스탯/장비/스킬 관리, 전투 기록 저장, 전투 화면 캔버스 렌더링에 초점이 맞춰져 있습니다.

## 실행 방법

Python 3이 설치되어 있으면 별도 패키지 설치 없이 실행할 수 있습니다.

```bash
python server.py
```

브라우저에서 아래 주소를 엽니다.

```text
http://127.0.0.1:8000/
```

포트를 바꾸고 싶으면 `PORT` 환경 변수를 지정합니다.

```bash
PORT=8080 python server.py
```

Windows PowerShell에서는 다음처럼 실행할 수 있습니다.

```powershell
$env:PORT = "8080"
python server.py
```

## 주요 기능

- 전투: 팀 vs 몬스터, 팀 vs 팀 자동 전투를 실행하고 전투 화면을 캔버스로 표시합니다. 전투 화면에는 전투 화면/전투 로그 탭이 있으며, 전투 로그는 세션 중 발생한 피해와 회복 이벤트를 아군 연파랑색, 적군 연한 붉은색으로 구분해 보여줍니다. 전투는 시작, 중단, 결과 바로 보기로 조작할 수 있습니다.
- 팀 편성: 저장된 캐릭터를 조합해 최대 10명 기준의 전투 팀을 구성합니다.
- 캐릭터 관리: 캐릭터 이름, 초상화, 계열, 진영, 장착 스킬을 관리합니다.
- 스탯 관리: 힘, 체력, 민첩, 집중, 지능, 지혜를 배분하고 파생 능력치를 확인합니다.
- 장비 착용: 주무기, 보조무기, 상의, 하의, 장신구, 특수장비 슬롯에 아이템을 장착합니다.
- 장비 예외: 캐릭터별로 추가 무기 슬롯을 최대 5개까지 열고 양손 무기를 슬롯 하나에 착용하도록 설정할 수 있습니다.
- 장비 세트: 캐릭터별 장비 프리셋을 최대 3개까지 복제·전환·삭제하며 선택한 세트로 능력치와 무기 공격을 계산합니다.
- 전투 장비 교체: 스킬 액션으로 자신이나 아군의 저장된 장비 세트를 교체하고 현재 자원·효과·쿨타임을 유지합니다.
- 전투 대기·부활: 캐릭터별 진입 지연, 부활 횟수·지연·HP 비율을 설정하며 대기자가 남아 있는 동안에는 패배하지 않습니다.
- 팀 전투 규칙: 팀별로 주는 피해·치유·스킬 자원 비용·재사용 대기시간 배율을 설정하고 양 진영에 독립적으로 적용합니다.
- 편성 시너지: 팀별 진영·계열 인원 조건을 여러 개 설정하고 충족된 피해·치유·비용·쿨타임 배율을 함께 적용합니다.
- 스킬 복제: 대기 중인 아군을 포함해 지정 순번의 액티브 스킬을 최대 네 개의 런타임 슬롯에 복제하며 원본과 별도 쿨타임을 사용합니다.
- 팀 예비대: 팀 편성 순서와 선봉 인원 수를 기준으로 예비대를 구성하고, 선봉이 영구 사망하면 다음 예비대가 전투에 난입합니다.
- 예비대 교대: 스킬 액션으로 자신이나 아군을 지정 순번의 예비대와 교체하며 HP·자원·재사용 대기시간을 유지합니다.
- 부활 후속 규칙: 캐릭터별 부활 HP·MP·ST, 부활 직후 무적 시간과 사망 위치 또는 진영 시작 위치 복귀를 설정합니다.
- 런타임 규칙 변경: 스킬로 대상의 피해·치유·자원 비용·재사용 대기시간 배율을 일정 시간 변경합니다.
- 스킬 금지: 규칙 변경 액션에서 선택한 액티브·패시브·기본 공격·장비 연결 스킬 또는 모든 스킬을 지속시간 동안 차단합니다.
- 받는 효과 규칙: 규칙 변경 액션으로 받는 피해와 받는 치유 배율을 조절하며, 받는 치유 0%는 모든 회복을 차단합니다.
- 규칙 무효화: 편성 시너지 또는 장비 능력치·무기 효과를 대상별로 일정 시간 비활성화하고 만료 시 복구합니다.
- 능력치 규칙: 버프로 능력치를 특정 값에 고정·삭제하거나 적용 시점의 다른 원본 능력치 일부를 전환할 수 있습니다.
- 다음 스킬 보정: 다음 액티브·채널링 1회의 시전시간, 자원 비용, 쿨타임을 각각 조절할 수 있습니다.
- 피해 반사: 기본 공격·스킬 범위를 구분해 실제 받은 피해를 반사하며, 대리 수신 피해와 재귀 차단을 지원합니다.
- 무기별 독립 공격: 여러 무기를 장착하면 각 무기가 자체 사거리·시전시간·공격 주기·연결 스킬로 독립 공격합니다.
- 집중 공격 감산: 여러 무기가 같은 대상을 추적할 때 캐릭터별 추가 무기 감산율을 각 무기 피해에 적용합니다.
- 형태별 스킬: 변신마다 사용할 액티브 스킬 목록과 기본 공격 스킬을 지정하고 만료 시 원래 구성으로 복귀합니다.
- 아이템 관리: 장비 슬롯, 무기/방어구 카테고리, 능력치 보정, 공격 스킬 연결을 관리합니다.
- 스킬 관리: 기본 정보·발동 설정·비용·액션 Section에서 스킬 슬롯, 재사용대기시간, 자원 소모, 피해/회복/이동 등 다중 액션을 편집합니다. 넓은 화면은 관련 값을 2열로, 좁은 화면은 1열로 표시합니다.
- 스킬 설명: 공통 설명을 입력하고 목록에서 요약을 확인합니다. 몬스터 편집에서도 사용할 스킬을 여러 개 선택할 수 있습니다.
- 액션별 대상: 한 스킬의 적 피해와 아군 회복이 각각의 사거리 안에서 별도 대상을 찾습니다. 원거리 투사체와 광역 범위 표시도 액션별로 적용합니다.
- 연쇄 피해·회복: 추가 연쇄 횟수와 대상 사이 거리를 설정하며, 같은 대상은 한 번만 적용합니다. 첫 명중 시 연쇄를 적용하고 연결 경로를 표시합니다.
- 상태·버프: 능력치 증감과 기절·이동 불가·침묵을 적용합니다. 효과 ID, 지속시간, 중첩·갱신 방식, 최대 중첩을 편집하고 ID로 해제할 수 있습니다. 만료·해제 시 원래 능력치로 복구됩니다.
- 주기 효과: 상태·버프에 피해 또는 HP/MP/ST/BP 회복을 연결합니다. 적용 간격과 중첩당 수치를 편집하며, 기존 지속시간·중첩·해제 규칙을 따릅니다.
- 해제·면역: 효과의 물리/마법/일반 분류, 이로운/해로운 성격, 해제 가능 여부를 설정합니다. ID·분류·전체 해제와 특정 분류·상태의 새 부여를 막는 면역을 지원합니다.
- 전투 이벤트: 시전 시작·완료·중단, 적중·피격·치유·사망을 공통 이벤트로 전달합니다. 전투 로그의 상세 화면에서 종류별로 확인할 수 있습니다.
- 패시브: 스킬 슬롯을 패시브로 정하고 적중·피격·시전 완료·회복·적 처치 조건과 확률을 설정합니다. 장착 후 자원·쿨타임에 따라 즉시 발동하며, 패시브끼리 연쇄 발동하지 않습니다.
- 소환 Entity: 스킬 편집 안에서 독립 개체를 검색·선택·생성·수정·복사·삭제하고 저장 전 전투 미리보기를 실행합니다. [Entity 관리 안내](docs/ENTITIES.md)를 참고하세요. 서버 변경 후 재시작이 필요합니다.
- 몬스터 관리: 전투 대상 몬스터의 능력치와 초상화를 관리합니다.
- 진영 관리: 진영 목록과 캐릭터 소속을 관리합니다.
- 장비 카테고리 관리: 무기/방어구 카테고리, 착용 방식, 사정거리, 공격 타입을 관리합니다.
- 전투 기록: 전투 결과, 참여 멤버, 소요 시간을 저장하고 조회합니다.
- 페이지 조정: 화면별 주요 영역의 크기와 여백을 로컬 설정으로 조정합니다.
- 로그: 앱 내부 로딩, 저장, 오류 로그를 확인합니다.

## 데이터와 API

`server.py`는 `/api/<name>` 요청을 `data/<name>.json` 파일에 매핑합니다. 예외적으로 `/api/records`는 `data/battle-records.json`에 저장됩니다.

| API | 파일 | 설명 |
| --- | --- | --- |
| `/api/monsters` | `data/monsters.json` | 몬스터 능력치와 초상화 |
| `/api/characters` | `data/characters.json` | 캐릭터 능력치, 스탯, 장비, 스킬, 진영 |
| `/api/factions` | `data/factions.json` | 진영 목록 |
| `/api/teams` | `data/teams.json` | 팀 이름과 멤버 ID |
| `/api/records` | `data/battle-records.json` | 전투 기록 |
| `/api/items` | `data/items.json` | 장비 아이템 |
| `/api/categories` | `data/categories.json` | 무기/방어구 카테고리 |
| `/api/skills` | `data/skills.json` | 스킬, 자원 소모, 액션 |

저장 API는 `PUT` 또는 `POST`를 지원하며, JSON 루트가 배열이어야 합니다.

이 규칙은 위 표의 일반 데이터 API에 적용됩니다. 별도 API는 다음과 같습니다.

| API | 저장 위치/역할 | 메서드·본문 |
| --- | --- | --- |
| `/api/image-settings` | `data/image-generator-settings.json` | GET/PUT, 설정 객체 |
| `/api/entities/`, `/api/entities/<id>` | `data/entities/<id>.json` | 목록/단일 GET, 생성 POST, 수정 PUT, 삭제 DELETE; [상세 규칙](docs/ENTITIES.md) |
| `/api/image/generate` | 서버 기반 이미지 생성 | POST, 생성 옵션 객체 |
| `/api/assets/<kind>`, `/api/assets-url/<kind>` | 허용된 이미지 폴더에 저장 | POST, 이미지 데이터 또는 URL |
| `/api/open-folder/<kind>` | 허용된 이미지 폴더 열기 | POST |

스킬 및 Entity 조회 시 이전 형식의 소환 정의가 Entity 파일로 자동 이전될 수 있습니다. 상세한 필드와 참조 관계는 [데이터 구조](docs/data_structure.md)를 참고합니다.

## 전투 시스템 개요

- 전투는 `setTimeout` 기반 `gameLoop()`에서 경과 시간에 따라 틱을 진행하고 Canvas 2D를 렌더링합니다.
- 유닛은 사정거리까지 이동한 뒤 공격하거나 스킬을 시전합니다.
- HP가 0 이하가 되면 사망 처리됩니다.
- MP, ST, BP 같은 자원을 사용합니다.
- ST가 고갈되면 이동속도와 공격속도에 페널티가 적용됩니다.
- 물리 피해는 방어력, 마법 피해는 저항력의 영향을 받습니다.
- BP는 HP보다 먼저 피해를 받으며, 남는 피해가 HP로 이월되지 않는 보호막 자원으로 설계되어 있습니다.
- 전투 이벤트 로그는 현재 전투 세션 안에서만 유지되며, 새 전투 시작/전투 중단/초기화/전투 종료 시 비워집니다.
- 전투 루프는 시간 기반 타이머로 백그라운드 진행을 이어가되, 브라우저의 타이머 제한과 루프당 최대 틱 수 때문에 진행 속도는 달라질 수 있습니다.
- 전투 중단은 현재 전투를 즉시 멈추며 전투 기록에 저장하지 않습니다.
- 결과 바로 보기는 전투 화면을 기다리지 않고 내부 전투 틱을 빠르게 진행해 승패 결과와 전투 기록을 생성합니다.
- 전투 종료 시 결과, 멤버별 HP/MP/ST·역할·DPS와 최근 최대 1,000건의 상세 이벤트를 저장합니다. 누적 피해·받은 피해·치유 통계 전체를 멤버 필드로 저장하는 형식은 아닙니다.

## 개발 메모

- 외부 프론트엔드 빌드 과정은 없습니다. HTML, CSS, JavaScript를 브라우저가 직접 로드합니다.

- CSS/JS를 수정한 뒤 브라우저 캐시로 예전 파일이 실행될 수 있으므로, `index.html`의 관련 정적 파일 버전 쿼리도 함께 갱신합니다.
- 데이터 저장은 서버가 `data/*.json` 파일을 직접 덮어쓰는 방식입니다. 중요한 데이터는 변경 전 백업을 권장합니다.
- 이미지 자산은 `assets/images/` 아래에 용도별로 저장합니다. 초상화는 `portraits/`, 스킬 이미지는 `skills/`, 아이템 이미지는 `items/`, 공용 아이콘은 `icons/`를 사용합니다.

- 브라우저에서 HTML 파일을 직접 열면 저장 API가 동작하지 않습니다. 데이터 저장까지 확인하려면 `server.py`로 실행해야 합니다.
- `__pycache__`는 Python 실행 중 생성되는 캐시 폴더라 소스 관리 대상에서 제외해도 됩니다.

## 이미지 생성 설정

생성·저장 상태는 버튼 바로 아래에도 표시됩니다. 잘못된 생성 입력은 페이지를 위로 이동시키지 않고 안내하며, 재생성 중에는 이전 미리보기를 유지합니다. 저장 이름은 한글·공백을 보존하여 `숲의 기사.png`처럼 저장하고, 같은 파일이 있으면 `숲의 기사-2.png`처럼 번호를 붙입니다. 파일명에 쓸 수 없는 문자는 치환됩니다. 이 파일명 변경을 적용하려면 Python 서버를 재시작하세요.

**내 스타일 관리**에서 스타일 세팅에 이름을 붙여 여러 개 저장할 수 있습니다. 이름과 스타일 세팅을 입력하고 **새 스타일로 저장**, 목록에서 선택 후 **불러오기**, 이름·내용 변경 후 **선택 스타일 수정**, **삭제**를 사용합니다. 스타일 목록은 생성 실행과 별개로 서버에 저장되어 새로고침 후에도 유지됩니다. 저장 대상은 이름과 스타일 문장이며 제시어·AI·모델·이미지 크기는 변경하지 않습니다.

이미지 생성 페이지는 기본값으로 Puter.js의 브라우저 기반 이미지 생성을 사용합니다. 앱 개발자용 API 키 없이 사용할 수 있으며, 사용자가 Puter 계정으로 인증해 쓰는 방식입니다. 생성된 이미지는 화면에서 확인한 뒤 저장 이름을 지정하고 `이미지 폴더에 저장`을 누르면 `assets/images/generated/` 폴더에 저장됩니다.

Puter 모델을 비우면 `gpt-image-2`를 사용하며, 모델을 직접 입력하면 Puter가 해당 모델의 제공자를 선택합니다. 기존 기본값 `gpt-image-1-mini`는 Puter에서 제공 종료되었습니다. 저장된 모델에 이 이름이 직접 들어 있다면 입력칸을 비우거나 지원 모델로 변경하세요. 계정의 사용량·잔액 제한은 별도로 적용됩니다. [오류 확인 및 검증 범위](docs/IMAGE_GENERATION.md)를 참고하세요.

생성에 성공하면 마지막 스타일 프리셋, 스타일 문장, AI 제공자, 모델, 이미지 크기, 시드, 최종 프롬프트가 `data/image-generator-settings.json`에 저장됩니다. 서버를 다시 켜도 이미지 생성 페이지를 열면 이 설정을 다시 불러옵니다.

Puter를 사용할 때는 이미지 생성 페이지의 `Puter 사용량` 영역에서 `puter.auth.getMonthlyUsage()` 기준 남은 월 사용량을 퍼센트 막대로 확인할 수 있습니다. 저장 버튼 옆의 `폴더 열기` 버튼으로 `assets/images/generated/` 폴더를 바로 열 수 있습니다.

Hugging Face Inference API를 쓰려면 실행 전에 `HF_TOKEN` 환경변수를 설정하고, 화면의 AI 선택을 `Hugging Face`로 바꾸면 됩니다. 모델 입력칸을 비우면 `HF_IMAGE_MODEL` 환경변수 또는 기본 Stable Diffusion XL 모델을 사용합니다.

```powershell
$env:HF_TOKEN = "your_huggingface_token"
$env:HF_IMAGE_MODEL = "stabilityai/stable-diffusion-xl-base-1.0"
python server.py
```

## 확장 스킬 기능과 상세 이벤트

계산계수에서 전투 누적 실제 피해량, 누적 이동 거리, 대상의 전체 또는 특정 ID 효과 중첩 합계, 생존한 자기 소환수 수와 같은 스킬 실행의 직전·누적 실제 피해·치유량을 선택할 수 있습니다. 실제 피해를 후속 회복에 사용하거나 실제 치유를 후속 피해에 사용해 전환형 스킬을 구성할 수 있습니다. 정의와 제한은 [스킬 엔진 안내](docs/SKILL_ENGINE.md)를 참고하세요.

상태·버프에는 사용 횟수와 적중·피격·회복·시전 완료 소모 조건을 지정할 수 있습니다. 피해 무시 모드로 다음 N회 피해를 막는 효과도 구성할 수 있습니다.

계산계수에서 이번 시전의 전체 또는 HP·MP·ST·BP별 실제 스킬 비용 지불량을 사용할 수 있습니다. 채널링과 패시브에서도 해당 실행이 최초로 지불한 값을 유지합니다.

자원 감소 액션으로 대상의 HP·MP·ST·BP를 줄이고, 직전 액션 또는 현재 실행에서 실제로 감소한 양을 후속 액션 계수로 사용할 수 있습니다.

전투 종료 시 최근 1,000건의 상세 전투 이벤트를 전투 기록에 함께 저장합니다. 전투 기록 화면에서 이벤트별 시간, 출처, 대상, 스킬, 실제 수치와 사유를 펼쳐 확인할 수 있습니다.

캐릭터와 몬스터에 커스텀 자원을 정의하고 `custom:<id>`로 스킬 비용·회복·감소·주기 효과·지속 지역에서 사용할 수 있습니다. 전투를 초기화하면 설정한 초기값으로 돌아갑니다.

지속 지역 효과는 대상 또는 시전자 위치에 고정된 원형 범위를 만들고 설정한 간격마다 피해·회복·자원 감소·강제 이동·상태·버프를 적용합니다. 필드 수명과 상태·버프의 수명을 따로 설정할 수 있으며 반경·간격·최대 대상 수와 전투 화면의 남은 범위를 확인할 수 있습니다.

지속 지역 효과에 밀치기·넉백·끌어오기를 설정할 수 있습니다. 매 주기마다 고정된 필드 중심을 기준으로 대상을 이동시키며 기존 유닛 충돌과 전장 경계 규칙을 적용합니다.

상태이상·버프 추가와 해제 액션에도 원형 반경, 중심, 최대 대상 수를 설정할 수 있습니다. 광역 해제는 해제 조건에 맞는 유닛만 최대 대상 수에 포함합니다.

이동 액션은 돌진·순간이동과 대상 넉백·밀치기·끌어오기를 지원합니다. 돌진과 강제 이동은 유닛 및 전장 경계 앞에서 멈추며, 순간이동은 점유된 위치로 이동하지 않습니다.

피해 대리 버프는 버프 시전자가 대상의 피해 일부를 대신 받게 합니다. 기본 공격·스킬·전체 피해 범위와 분배율, 다중 보호자의 우선순위를 편집할 수 있으며 각 수신자의 보호막과 방어력을 따로 적용합니다.

소환 액션은 소환수가 소환자의 기본 공격·스킬·전체 피해 중 지정 비율을 대신 받도록 설정할 수 있습니다. 해로운 상태이상도 전체 또는 일반·물리·마법 분류별로 살아 있는 소환수에게 이전할 수 있으며, 여러 소환수의 처리 우선순위를 지정할 수 있습니다.

소환 위치는 시전자 주변 또는 사거리 안에서 선택한 아군·적군 주변으로 지정할 수 있습니다. 대상 중심 소환도 생성된 Entity의 진영과 소유자는 시전자를 따릅니다.

소환 액션별로 HP·MP·ST·공격력·마력·방어력·저항력·이동속도의 소환자 계승 비율을 설정할 수 있습니다. 계승값은 소환 순간에 계산되며 Entity 원본 데이터에는 영향을 주지 않습니다.

스킬 액션의 대상을 `내 소환수`로 지정하면 시전자가 직접 소유한 소환수만 피해·회복·이동·상태·버프·해제 대상으로 선택합니다. 광역과 지속 필드에도 동일한 소유권 필터가 적용됩니다. `소환수 명령` 액션으로 소유한 소환수를 정지, 행동 재개, 시전자 옆으로 복귀, 소환 해제할 수 있으며 반경과 최대 대상 수로 여러 소환수를 함께 제어할 수 있습니다.

아군 부활 액션은 완전히 사망한 일반 아군을 지정한 HP·MP·ST와 무적 시간으로 되살립니다. 예비대는 인원 제한을 넘겨 임시 증원할 수 있고, 교대에 지속시간을 설정하면 만료 또는 투입 유닛 사망 시 원래 유닛이 복귀합니다.

변신 액션은 시전자에게 공격력·마력·방어력·저항력·이동속도·사거리·공격 간격·기본 시전시간 변경을 한꺼번에 적용합니다. 고정값과 기본 능력치 비율을 선택하며 새 변신 적용, 만료, 사망, 전투 종료 시 정확히 복원합니다.

액션 편집기에서 대상 HP 상한(기본 100%, 제한 없음)과 대상별 쿨타임(기본 0초)을 설정할 수 있습니다. 광역·연쇄를 포함하여 각 대상에 독립적으로 적용합니다.

스킬 편집기의 채널링 유지시간을 설정하면 일반 시전 후 액션을 주기적으로 반복합니다. 기본 유지시간은 0초(사용 안 함), 간격은 1초이며 피해 시 중단이 기본입니다. 자원은 시작 시 한 번 소모하고 쿨타임은 완료·중단 시 시작합니다. 자세한 규칙은 [스킬 엔진 안내](docs/SKILL_ENGINE.md)를 참고하세요.
## 아이콘 관리

기존·신규 아이콘은 **배경 자동 제거**가 기본 적용됩니다. 원본 이미지는 보존하며, 아이콘 관리에서 체크무늬 미리보기와 **제거 강도**를 확인하고 저장할 수 있습니다. 그림이 지워지면 강도를 낮추거나 자동 제거를 끄세요. 단색·유사색 배경용이므로 복잡한 배경은 남을 수 있습니다.

상단 **아이콘 관리**에서 클래스·장비 슬롯·장비 카테고리·스킬 유형·진영의 대상 단어에 대체 표시명과 이미지를 지정할 수 있습니다. 저장하면 관련 목록에 공통 적용되고 새로고침 후에도 유지됩니다. [사용 안내와 적용 범위](docs/ICONS.md)를 참고하세요.
